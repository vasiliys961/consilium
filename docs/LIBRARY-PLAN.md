# Личная библиотека врача: папка, браузер и смысловой поиск

Уточнено с пользователем 12 ноября 2026. **По последующему поручению пользователя выполнен базовый перенос. Оставшиеся пункты ниже не считаются автоматически завершёнными.** Детализация задачи C8 из [дорожной карты](ROADMAP.md).

## Решение по хранению

Два равноправных источника в одной библиотеке:

| Источник | Что хранится | Как используется |
|---|---|---|
| Выбранная врачом папка на компьютере | Исходные книги, руководства и статьи; индекс, связанный с конкретными файлами и их версиями | Основной объём библиотеки без необходимости копировать все книги в браузер |
| Библиотека браузера | Выбранные книги, текст страниц, фрагменты, метаданные и эмбеддинги в IndexedDB | Быстрый доступ и смысловой поиск по доступным на этом устройстве материалам |

Врач выбирает, какие книги оставить только в папке, какие импортировать в браузер и какие держать в обоих местах. Одна книга не должна дублироваться в результатах из-за двух копий. Идентификация — по содержимому и версии/изданию; новое издание не подменяет старое молча.

Для браузера показывать занимаемый объём и доступную ёмкость, а не обещать фиксированное число книг. Предусмотреть удаление, экспорт и восстановление библиотеки, перенос выбранных книг. Исходники и индекс удаляются различимыми действиями. Очистка данных браузера и смена адреса приложения требуют восстановления/миграции, а не считаются автоматическим переносом.

Папка доступна только через выбранный врачом способ доступа. Если папка недоступна на текущем устройстве, показать это и продолжить поиск по доступным книгам. Само наличие папки на компьютере не делает её доступной телефону из другой сети. Серверная синхронизация и размещение книг на сервере в это решение автоматически не входят.

## Найденная материнская основа

Проверена исходная копия `concilium-opus-global-chat`:

- `app/library/page.tsx`: импорт PDF, страницы, разбиение на фрагменты, быстрый/полный режимы индексации, пакетная векторизация, повторная индексация и её остановка.
- `lib/library-db.ts`: IndexedDB `MedicalLibraryDB`, версия схемы 5; документы, фрагменты, исходные файлы, эмбеддинги, страницы-изображения и миниатюры.
- `lib/embeddings.ts`: браузерная векторизация через Transformers.js, `Xenova/multilingual-e5-small`, 384 измерения, префиксы `query:`/`passage:`, нормализация и квантование Int8.
- `lib/library-db.ts`: гибридное ранжирование, в существующем коде вес словесного сигнала 0.4, смыслового — 0.6; привязка результата к документу и странице.
- `lib/library-service.ts`, `components/LibrarySearch.tsx`: поиск по запросу и подготовка найденных фрагментов для контекста модели; поиск включается по условию активности.

Это подтверждение наличия реализации в материнском коде, а не готового переноса в Concilium. Текущий код загрузчика эмбеддингов использует локальные `/models/` и `/ort/` с отключённой загрузкой моделей извне. Наличие нужных ресурсов и реальное вычисление вектора в новой сборке предстоит проверить. Старый комментарий о CDN не считать описанием фактической конфигурации.

Переносить рабочие части, структуру хранения и смысловой поиск. Отдельно адаптировать доступ к папке, индексы, UI, формат источников и связь с текущими случаями. Не создавать второй несвязанный поисковик. Модель текстовых эмбеддингов — инструмент поиска, а не тяжёлый клинический детектор; её возможность работы на телефоне проверяется отдельно.

## Как библиотека участвует в разборе

1. Врач задаёт клинический вопрос и при необходимости добавляет материалы.
2. Доступен переключатель **«Предлагать материалы моей библиотеки»**. Также можно вручную нажать **«Найти в библиотеке»** или ограничить поиск выбранными книгами.
3. По текущему вопросу и уместному контексту случая выполняется локальный поиск по доступным индексам. Сначала находится подходящее содержание, а не только название книги.
4. Приложение предлагает конкретные книги, главы и страницы: например, «В библиотеке есть подходящие материалы. Использовать в этом разборе?» Видны место хранения, издание, фрагмент и причина предложения. Врач может открыть страницу, выбрать материалы, отказаться или продолжить без библиотеки.
5. После выбора в разбор передаются релевантные фрагменты с идентификаторами источников, а не все книги целиком. Подготовка и проверка отправляемой копии остаются частью существующего пути.
6. В ленте видно, какие книги и страницы использованы для этого ответа. Вывод связан с реальным фрагментом; само семантическое сходство ещё не подтверждает клинический тезис.
7. Следующий вопрос заново ищет нужные места по уже готовому индексу. Импорт и векторизация всей книги не повторяются. Ранее выбранная книга может оставаться предпочтительной, но старый отрывок не прикрепляется автоматически к любому новому вопросу.

Библиотека — дополнительный инструмент. Её отключение, отсутствие подходящих книг или сбой поиска не останавливают основной разбор. Личная книга принимается без проверки покупки или происхождения файла, как уже согласовано в продуктовой политике.

## Поиск и индексация

- Совместить смысловой поиск и поиск по словам, сокращениям, названиям лекарств и точным значениям. Конкретные веса ранжирования проверить на врачебных запросах, а не считать материнские константы окончательными.
- Разбивать текст с привязкой к страницам и разделам. Для сканов учитывать OCR и возможность сверки с оригиналом.
- Сохранять модель, версию индекса, полноту покрытия страниц и векторизации. Статусы: не индексирована, индексируется, частично готова, готова, ошибка. Часть векторов не выдаётся за полностью готовую книгу.
- Поддержать индексацию порциями, прогресс, отмену и продолжение, чтобы большая книга не блокировала интерфейс.
- При недоступности эмбеддингов сохранить поиск по словам и явно назвать текущий режим. Не выдавать такой откат за смысловой поиск.
- Обновление файла или модели вызывает необходимую переиндексацию; неизменённые книги не обрабатываются заново без причины.
- Проверить мультиязычные запросы и релевантность фрагментов; найденная близость по смыслу не заменяет проверку источника и применимости.

## Критерии готовности переноса

- Одну книгу можно использовать из папки, другую — из браузера; общий запрос находит обе, когда оба хранилища доступны.
- Большая книга импортируется один раз, повторный разбор не загружает и не векторизует её заново.
- Смысловой запрос находит подходящий фрагмент при отличающихся формулировках; при этом результат открывается на правильной странице нужного издания.
- Подключение найденного фрагмента и отказ от библиотеки проверены от действия врача до готового ответа в ленте.
- В ответ попадают только выбранные фрагменты; книги не публикуются и не переносятся автоматически на сервер.
- Сбой модели эмбеддингов, частичный индекс, переполнение браузерного хранилища и недоступная папка имеют понятный результат без потери книг и случая.
- Проверены сохранение, повторное открытие, экспорт/восстановление, отсутствие дублей и поведение при изменении книги.

## Фактический перенос 12 ноября 2026

- `/library`: импорт PDF с текстовым слоем, TXT/MD до 250 МБ. Страницы PDF сохраняют исходную нумерацию. Чтение, фрагментация и индексация происходят в браузере. Для сканированных книг без текстового слоя пока требуется предварительный OCR.
- Перенесены материнские IndexedDB `MedicalLibraryDB` v5 и текстовые эмбеддинги multilingual-e5-small (384, Int8); визуальный CLIP-поиск не переносился. Полнота векторизации отмечается только после окончания всех пакетов. Остановленный индекс можно продолжить.
- `npm run setup:library-models` устанавливает модель и WASM в локальные `public/models` и `public/ort`. Во время поиска удалённые модели запрещены; книги не отправляются сервису эмбеддингов. Ресурсы установлены в текущем рабочем месте.
- Выбранные файлы хранятся в браузере. Выбор папки через File System Access API (Chrome/Edge) сохраняет оригиналы на диске и дескрипторы файлов в IndexedDB. Браузеры без этого API предлагают импорт копий из папки. Для чтения оригинала после отзыва доступа потребуется заново подключить папку. Автосинхронизации нет.
- В окне разбора по текущему вопросу автоматически появляются предложения книги/страницы/текста. Врач отмечает фрагменты. Только они включаются в referenceFiles, проходят локальную проверку и получают стабильные passageId и ссылку на страницу в результатах. При изменении вопроса прежний выбор не переносится молча.
- Раздел использует переключатель языка приложения. Поиск не привязан к языку интерфейса; цитируемые фрагменты остаются на языке оригинала. Подписи и подробные пояснения раздела добавлены во все 10 языков приложения.
- Семантический поиск является подбором кандидатов, не доказательством применимости. Проверка на синтетической книге выявила ошибку свободного RU→EN запроса. Добавлен консервативный порог семантической близости и расширение явно названных медицинских понятий; дальнейшая оценка на реальных книгах остаётся открытой.
- 259 тестов: хранилище, страницы/перекрытие фрагментов, продолжение индекса, удаление, поиск, сохранение происхождения через обе стадии privacy-review, цитирование выбранного фрагмента даже без буквального совпадения с вопросом. Сборка и TypeScript проходят.

Пока не завершены: дедупликация импортов по содержимому, контроль версии файлов, управление квотой, архив всей библиотеки, пакетный OCR книг и качество подбора на врачебном контрольном наборе. Книги не входят в зашифрованную резервную копию клинических случаев; оригиналы следует сохранять отдельно.

Браузерная проверка итоговой версии: импорт синтетического двухстраничного PDF, завершение локального индекса, RU-запрос в EN-интерфейсе → релевантная страница EN-книги, отметка страницы в случае и её появление в privacy-review с исходным заголовком и номером. Внешний запрос отменён после проверки состава отправки.
