# C4 — приём файлов со смартфона: подтверждённая передача

**Дата:** 16.11.2026. **Статус:** отдельная ветка разработки, без запуска/перезапуска Preview 3207 и без доступа к реальным мобильным устройствам.

## Врачебный результат

При передаче документа, фото, аудио или короткого видео со смартфона система различает:
1. **Файл поставлен в очередь на компьютере** — это ещё не гарантия сохранения.
2. **Компьютер подтвердил приём файла** — только после того, как пользовательский обработчик приёма успешно завершился и следующий опрос подтвердил обработанный ID.
3. **Связь прервана** — файл остаётся виден на телефоне, повторное обращение к серверу не сообщает ложный успех; статус проверяется при возвращении вкладки или Wi-Fi.

Повторный POST с тем же одноразовым идентификатором запроса в пределах сессии не создаёт дубля, даже если первый HTTP-ответ потерян. При несовпадении содержимого SHA-256 (включая одинаковый размер) сервер возвращает конфликт. Ключ запроса создан через `crypto.getRandomValues`, доступный для ограниченной LAN HTTP-страницы смартфона; `crypto.randomUUID` на HTTP не требуется. Идентификатор сессии и статус запрашиваются POST, а не в URL.

Включены регрессионные тесты на повторный опрос без подтверждения, перезапрос после потерянного ответа, конфликт содержимого, подтверждение, неизвестную/истёкшую сессию. Все тесты бесплатные и не используют медицинские модели.

**Ограничение:** получение в обработчик случая не обязательно равно физическому сохранению на диск или резервному копированию; в автономной «Папке приёма» запись в IndexedDB завершается до подтверждения. Серверную сессию хранит память Next.js — рестарт сервера всё ещё обрывает очередь. Это отдельная цель для дальнейшей работы, а не реализованная надёжная постоянная очередь.

## Проверка на настоящем iPhone/Android — ещё не выполнена

Когда Preview будет специально запущен пользователем, проверить на двух устройствах:
1. Подключение по QR в одной Wi-Fi сети; без HTTPS доступны выбор файла/камера, но встроенная прямая запись микрофона остаётся ограниченной браузером.
2. PDF из 2–3 сканированных страниц и обычное фото: визуальное подтверждение, правильный порядок страниц, доступность файла в приёмнике.
3. Видео/аудио размером до 8 МБ: статус в очереди, затем подтверждение компьютера; неподдержанные кодеки должны давать конкретную ошибку.
4. Прервать Wi-Fi после нажатия «Отправить», восстановить сеть, проверить отсутствие дублей и корректное подтверждение.
5. Свернуть Safari/Chrome, вернуться после 1–3 минут: проверить повторную проверку квитанции и восстановление ссылки.
6. Сохранить исходный PDF/изображение в выбранную папку и сравнить размер/хеш; убедиться, что файл не отправлен модели автоматически.
7. Создать длинный случай, несколько раз добавить новые материалы, проверить возврат из фона, восстановление сохранённых данных и потребление памяти.

Эти испытания невозможно заменить GitHub Actions: ни реальная камера iPhone, ни выбор файлов Android, ни поведение мобильных ОС в фоне здесь не проверялись.

## Границы и безопасность

- Ни один файл не отправляется медицинскому API при передаче в «Папку приёма».
- Существующий локальный HTTP-ретранслятор ограничен телефоном и LAN, он **не шифрует** содержимое в сети. Для конфиденциальных медицинских данных требуется доверенный HTTPS или отдельный защищённый канал.
- Не создавать новую фоновую службу, не менять `main`, не публиковать и не запускать платную инфраструктуру без разрешения.
