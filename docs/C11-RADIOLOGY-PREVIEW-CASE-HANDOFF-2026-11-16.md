# C11 — Radiology: изоляция двух приложений и корректное возвращение результата

Дата: 16 ноября 2026. Задача: врач из клинического случая нажимает **Opus Radiology** и использует уже установленный просмотрщик и предыдущие материалы без дополнительных технических настроек. Затрагивается только ветка ChatGPT; `main` и локальный порт 3107 не меняются.

## Обнаруженный дефект изоляции

В `integrations/radiology/web/app/viewer/page.tsx` четыре сообщения `postMessage` принимали и отправляли сведения об исходных файлах исключительно в `http://127.0.0.1:3107`. Для независимого Preview на `3207` это несовместимо с уже существовавшим `ConciliumBridge`, который корректно выбирал 3207, а сам Radiology работал на 3210. В результате DICOM/фотографии могли не передаваться между iframe и выбранным Preview. Это **не** основание объединять GitHub-ветки.

Исправлено: общий строгий helper `conciliumParentOrigin()` в дочернем Radiology, который выбирает **3107** для исходной установки и **3207** для Preview по `NEXT_PUBLIC_CONCILIUM_PREVIEW=1`. Без произвольного `targetOrigin='*'`, без доверия внешнему query-параметру, без обращения к другой локальной копии. И просмотрщик, и общий мост используют один и тот же выбор. Источником флага является `npm run dev:preview`, который передаёт окружение своей дочерней Radiology-службе на **3210**. Главный Codex не запускает этот код из ветки Preview.

## Исправлено при возвращении описания

- Нажатие врачом перехода на Radiology при уже установленном модуле инициирует локальный запуск и показывает просмотрщик без второй технической кнопки. Если модуль временно недоступен, не требуется вводить команды; данные остаются в случае.
- Оригиналы исследования привязываются к случаю по фактическому SHA-256. Они добавляются в очередь `serialCaseWrite` к самой свежей сохранённой карточке, а не накладываются поверх устаревшего React-снимка.
- Описание, подтверждённо переданное врачом из Radiology, возвращается в указанный ID случая и сохраняется как **неподписанный черновик** с явным предупреждением, что полнота прочитанных срезов не доказана. Ни один ранее записанный отчёт, протокол, анализ или врачебное решение не удаляется.
- Повторная передача полностью идентичного описания и набора файлов не удваивает отчёт. Изменённое описание сохраняется новой исторической записью.
- Связь с источником признаётся только тогда, когда **все SHA-256** материала присутствуют в текущем случае. Если часть материалов потеряна, описание остаётся доступным, но `fileKeys` пустой и источник обозначается неподтверждённым. Нельзя подставлять «все остальные снимки в случае» за использованное исследование.
- Закрытый, отсутствующий или удалённый случай не изменяется. Если файл позже заменён под тем же именем, его прежний отчёт остаётся в истории, но отмечается как устаревший в текущем анализе.

## Проверка и ограничения

Синтетические тесты: отдельные origin/порты, наследование preview-флага при запуске модуля, точный идентификатор случая, отказ при изменённом материале, неполной серии и закрытом случае, сохранность решений и параллельного черновика, повторная и новая версии отчёта. Тесты не используют пациентов, DICOM исследование, медицинские модели или оплачиваемые API.

**Нужна отдельная приёмка на Mac:** действительно открыть Radiology из синтетического случая в `http://127.0.0.1:3207`, убедиться в передаче небольшого тестового снимка, вернуть описание, снова открыть случай и проверить дату/источник; затем убедиться, что работа Codex на 3107 не затронута. Сам зелёный CI этого не доказывает. Тяжёлые детекторы и большие серии не входят в этот этап.
