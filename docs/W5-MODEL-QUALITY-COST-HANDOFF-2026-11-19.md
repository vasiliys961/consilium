# W5 — качество и стоимость моделей Doctor Opus: решение владельца / передача Codex

**Дата:** 19.11.2026. **Статус:** техническое задание для ревизии, **не разрешение на внедрение или слияние**.  
**Основа:** `chatgpt/codex-w4-workstation-continuity-20261118` (PR #96, SHA `0436c8be`); G-WORKSTATION остаётся `IN PROGRESS`.  
**Приоритет:** сначала текущая W4 → W5 клиническая приёмка. Затем три **небольшие независимые** оптимизации. Не переписывать архитектуру.

## Короткое решение

1. **Обновить устаревшие Haiku 4.5 → 5.5 только там, где роль неклиническая** (распорядитель, извлечение/оформление уже известных фактов), при условии прохождения регрессий. Haiku не должна становиться консультирующим врачом или оценщиком безопасности лекарств. **Не делать слепой search-and-replace**: в оригинальном Global-протоколе Haiku 4.5 используется при `isDiagnosticReport`, то есть маршрут может содержать клиническую интерпретацию. Такой маршрут отдельно классифицировать: если это новый диагностический вывод, рассматривать Sonnet 5.5; если только форматирование подтверждённых врачом данных — допускается проверяемая малая модель.
2. **Подорожание Gemini 4 Argon не даёт права автоматически снижать медицинское качество.** В коде `lib/gemini-policy.ts` на 01.12.2026 уже предусмотрено переключение `consiliumHypothesisModel()` с Argon на Flash при росте тарифа. Пересмотреть **только эту ценовую политику**: текстовые гипотезы сравнить Sonnet 5.5 ↔ Argon; визуальные исследования сравнить Gemini 3.8 Flash ↔ Argon на парных изображениях, с отдельной стратификацией ошибок. До сравнительной проверки Argon остаётся вариантом по качеству; опции в UI — без лишнего подтверждения на каждом шаге. **GPT-6.1 Sol оставить для независимого выбора исследований и клинического ракурса**, не делать его автоматической заменой визуального читателя без проверки мультимодального контракта/качества.
3. **Не запускать полный пятиэтапный консилиум для простых/рутинных вопросов.** Для обычной консультации — существующий модуль «Специалисты» с Sonnet 5.5; для сложной — Opus 5.5; полный консилиум — при существенной неопределённости, конфликте данных, высокой цене ошибки, мультиморбидности, значимых лекарственных рисках **или явном выборе врача**. Краткость текста не означает безопасность: «QTc 610 мс», «калий 6.8», тяжёлая гипоксемия, нестабильная гемодинамика и подобные короткие вопросы нельзя относить к простым. Не использовать Haiku в качестве клинического триажера/консультанта: экспериментальный PR #101 по трёхуровневой маршрутизации **не принят, не объединять**.

## Обязательные проверки перед внедрением

- Сравнить не менее 30 **независимых синтетических случаев** для каждого переключаемого клинического маршрута: короткие опасные вопросы, неотложные состояния, полипрагмазия, пожилые, дети, беременность, ХБП, QT, дозировки, противоречивые данные, RU/EN. Выделить опасные пропуски (FN), ложные тревоги (FP), источниковую точность, корректность ограничений, несохранение старого ответа как нового. Не подгонять набор под правила.
- Для визуальных моделей: **парные неизменные изображения** одного синтетического/публичного исследования с правильным контекстом, слепая оценка существенных находок, пропусков и уверенности; отдельно одиночный DICOM vs полная серия. Не заявлять эквивалентность только по агрегированному текстовому Clinical Index.
- Для Haiku 4.5→5.5 в форматирующих задачах: числа, десятичные разделители, единицы, дозы, отрицания, источники, локализация, отсутствие добавленных диагнозов/назначений; явно исключить новый клинический вывод из простого теста оформления.
- Для отказа от полного консилиума: обычный вопрос → **одна** содержательная консультация → сохранение/повторное открытие; сложный короткий вопрос → предложение сильной модели/консилиума; «Запустить консилиум» вручную работает всегда; отсутствует незаметный повторный платный запуск после ошибки или перехода.
- Для цены: проверить тарифы через доступный разрешённый провайдер в момент переключения; исправить устаревшую оценку `lib/cost.ts` (там Sonnet 5.5 3/15 USD/M, тогда как проверявшийся ранее тариф OpenRouter 2/10) и добавить явные расценки только реально используемых моделей. Фактический расход — `usage.cost`; при его отсутствии показывать **неизвестно / оценка**, никогда не выдавать оценку за квитанцию.
- Синтетические mock/unit/UI-тесты **не** подтверждают качество самих Haiku/Sonnet/Opus/Argon/Flash; реальные парные API-тесты выполнять **только после отдельного бюджета от владельца**. Не использовать реальные данные пациентов.

## Стратегия реализации для Codex

1. **Сначала короткий аудит** текущих вызовов моделей и уже существующих флагов/порогов. Представить минимальный diff и не дублировать уже реализованное.
2. Отдельные небольшие PR, **в `chatgpt-dev` с учётом зависимостей #95/#96**, каждый с тестами, CI и подтверждёнными границами качества. Не мержить этот документ автоматически как разрешение внедрить весь пакет.
3. Сохранить ручные переключатели, назначения ролей специалистов, безопасную приватность, идемпотентность, привязку к источникам и прежние успешные результаты. **Не менять `main`, 3107, продакшен, секреты, исходные standalone-приложения и данные Preview 3207.**
4. Не начинать Integration Hub, аватар и Unified Cost Manager; они отложены. Отдельный экспериментальный PR #101 с Haiku как клиническим консультантом **не объединять**.
5. После каждого изменения — локальная инженерная и, где применимо, реальная браузерная приёмка. Не объявлять клиническую пригодность по зелёному CI.

## Что считать успехом

Сохранено или повышено качество клинических решений **по сравнению с тем же исходным случаем**; опасные пропуски не увеличились в оцениваемой матрице; обычный вопрос не запускает ненужные платные роли; врач всё ещё может вручную запросить полный консилиум; стоимость по квитанциям/оценкам прозрачна; W4/W5 workflow и данные не повреждены.

**Нет разрешения** самостоятельно вызывать платные LLM, делать merge, менять рабочую станцию или утверждать клиническую эквивалентность.
