# C13 — адаптивный междисциплинарный консилиум (17 ноября 2026)

## Клиническая задача и принцип

**Сначала использовать готовые источники, затем обсуждать их смысл.** Результаты ECGFounder, визуального чтения ЭКГ, Gemini/Opus-модуля радиологии, дерматоскопии, гистологии, УЗИ, лабораторных документов и клинической истории используются как источники с указанными ограничениями. Роль ИИ-кардиолога в консилиуме **не заменяет и не повторяет** чтение ЭКГ, роль ИИ-радиолога — работу радиологической станции. Не считать непроведённое исследование нормальным.

## Что реализовано в PR #65

- Локальный детерминированный `planAdaptiveCouncil` выбирает **клинический ракурс** по вопросу, анамнезу и типам уже имеющихся материалов. Это **не диагноз, не дополнительный LLM-вызов** и не действие с файлом. Выбор ограничен списком допустимых специальностей. В чисто клиническом вопросе симптомы имеют приоритет перед наличием изображения; у дерматологических и гистопатологических исследований есть соответствующие ракурсы.
- Уже существующая роль `hypothesis` (в ноябре Gemini 4 Argon) получает профиль дифференциальных гипотез, роль `testChooser` (GPT-6.1 Sol) — приоритетный второй клинический ракурс для выбора действительно разделяющих гипотезы исследований. Это **две специализации существующих ролей, а не два дополнительных врача**.
- `challenger` (Claude Opus 5.5) остаётся независимым междисциплинарным критиком; `stewardship` (Claude Sonnet 5.5) проверяет препараты/органы/противопоказания; `checklist` (Claude Opus 5.5) синтезирует состоявшиеся мнения, фиксирует споры и отсутствие ответа. Версии провайдеров могут меняться существующей политикой модели. **Не более пяти ролей** на успешный запуск стандартного консилиума, итоговый пятый вызов не проводится, если все четыре первичные роли недоступны.
- Поле `clinicalPerspective` сохраняется вместе с каждой ролью в результате; в ленте врач видит её специализацию **и фактическую модель**. Интерфейс прямо говорит, что это роли ИИ-моделей, не независимые очные заключения врачей или новые оплаченные эксперты.
- В карточке случая по умолчанию остаётся автоматический выбор. Врач может один раз изменить клинический ракурс: сначала показаны предложенные для случая специальности, затем остальные разрешённые. Выбор передаётся **в реальный запрос** и включён в ключ защиты от платного повторного запуска. Нет второго окна подтверждения на каждого участника.
- **Смешанный случай автоматически НЕ включает платный консилиум**: врач нажимает отдельную кнопку консилиума либо ставит прежний флажок. Маршрутизация внутри уже разрешённого консилиума не добавляет новых вызовов. UI показывает «до пяти» вызовов и, если доступно, цену предыдущего консилиума **того же случая** с маркировкой «провайдер» или «расчёт»; не выдаёт её за гарантированную цену следующего запуска.

## Пример

Синтетический пациент: ФП, одышка, кашель, изменения КТ грудной клетки, снижение СКФ.

- Прочитанные ЭКГ, КТ, лаборатория входят в клинические данные с их источниками и ограничениями.
- Гипотезы — кардиологический ракурс, разделяющие исследования — пульмонологический; нефрологическая проблематика остаётся обязательным клиническим контекстом, но отдельный дорогостоящий нефролог не включается автоматически.
- Независимый критик проверяет, в том числе, не подменена ли первичная находка описанием модели; безопасность проверяет лекарства, СКФ и антитромботическую терапию; синтез обозначает нерешённые противоречия.
- Врач при желании вручную заменяет ведущий ракурс на нефрологический либо другой. Количество обязательных оплачиваемых моделей не увеличивается.

## Границы и приёмка

- Это **адаптивные клинические перспективы ИИ**, а не независимые консультации пяти специалистов с отдельной компетентностной валидацией. Их нельзя выдавать за врачебный консилиум в юридическом смысле.
- Разметка типа исследования и ключевые слова не гарантируют правильную специальность; врач может изменить предложенный вариант без дополнительных подтверждений.
- Переиспользование ранних результатов должно сохранять связку с исходным файлом и SHA-256, насколько её поддерживает существующая архитектура. Не считать неподписанный черновик радиологии достоверным отрицательным результатом.
- Проверка CI — синтетическая: набор клинических синдромов, адаптация, пять фиксированных ролей, отказ провайдера, неподменённые мнения, защита от повторов, наличие данных в интерфейсе. **Клиническая точность и Mac Preview 3207 пока не подтверждены**.
- Следующая клиническая приёмка: 1) один синдром без файлов, 2) ЭКГ + одышка + СКФ, 3) КТ + сопутствующая патология, 4) дерматоскопия с описанием, 5) гистология и неоднозначная формулировка, 6) отказ критика/отсутствие заключения, 7) локализация RU/EN, 8) однократное включение/отмена консилиума без повторных вызовов.
