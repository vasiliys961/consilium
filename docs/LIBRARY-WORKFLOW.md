# Библиотека: автоматический поиск и ответ по смыслу

## Работа врача

1. Добавьте PDF, TXT или Markdown. Для PDF при импорте строится полный локальный индекс: текст, подписи, таблицы, сноски и изображения страниц/областей. Обработку можно приостановить и продолжить. Оригинал сохраняйте отдельно.
2. Для ранее загруженной книги нажмите «Полный индекс · текст и изображения». Уже готовый индекс текущей версии не перестраивается; обработанные страницы сохраняются. Признак завершения появляется только после обработки всех страниц, отдельно от завершения текстовых эмбеддингов.
3. Введите вопрос обычными словами, при необходимости ограничьте поиск одной книгой и нажмите «Ответить по книге». Автоматический подбор включён по умолчанию. Номера страниц знать и отмечать фрагменты вручную не требуется.
4. Перед генерацией сохраняется существующая проверка отправляемой копии. Модель получает ограниченный набор найденных текстов и оригинальных страниц с рисунками/таблицами, а не всю книгу. Поиск, OCR и индексация локальные; генерация ответа — платный запрос через OpenRouter.
5. Ответ должен синтезировать сведения только из переданных источников, сохранить условия и исключения и ссылаться на фактически использованные страницы. Если материала недостаточно — сообщить об этом. Невалидные номера ссылок и ответ со статусом «answered» без ссылки блокируются.
6. В клиническом случае используйте тот же блок библиотеки. При запуске разбора приложение повторно находит материалы по актуальному вопросу и контексту случая и подключает их автоматически. Это литература, не наблюдения пациента: изображения книг не передаются в медицинские детекторы.
7. Для проверки доступны найденные материалы и ссылки книга/страница. Можно открыть оригинал, посмотреть другую страницу и включить ручной режим, отключив автоматический подбор.

## Что индексируется

- Текст PDF с сохранением исходного порядка текстового слоя, координатных признаков заголовков, подписей Figure/Рисунок, Table/Таблица и нижних примечаний.
- Подписи и таблицы сохраняются вместе с соседними строками и сносками. При поиске резервируется место для примечаний: длинная проза не должна вытеснять их из выбранного фрагмента.
- Изображения: вся страница и перекрывающиеся области для векторных схем, а также области встроенных растровых изображений по операциям и матрицам PDF. Поиск изображений основан на локальном CLIP, а не только на наличии подписи.
- Чисто текстовые страницы не добавляются визуальным поиском поверх текстовых результатов. Кандидаты объединяются по книге/странице, без дублирования одинаковой страницы.
- Страницы с недостаточным текстовым слоем проходят локальный OCR rus+eng. Отказ OCR не скрывается: показывается неполнота текстового покрытия, изображения остаются доступны.
- На момент ответа используются полные оригинальные страницы с рисунками/таблицами; поисковые миниатюры не подменяют оригинал.

## Модели и хранение

Текст: multilingual-e5-small. Изображения и англоязычные визуальные запросы: CLIP ViT-B/32. Веса устанавливаются через `npm run setup:library-models` и загружаются браузером с локального сервера. Книги и векторы не отправляются внешнему сервису при индексации/поиске. Нужные для развёртывания веса — около 146 МБ дополнительно к текстовой модели.

Для многоязычных запросов работают E5 и расширение медицинских терминов; найденный текст также помогает сформировать англоязычный запрос к визуальному индексу. Сам CLIP не является универсальным многоязычным медицинским поисковиком; поиск немаркированных изображений без подходящего текста нуждается в оценке на конкретном атласе.

Индекс и копии книг живут в IndexedDB того же браузера/адреса. Очистка данных браузера удаляет их. При подключении папки оригинал остаётся на диске; браузеру нужен доступ к нему для передачи полноценной страницы. Малые миниатюры и квантованные векторы сохраняются отдельно, не загружаются все изображения большой книги в оперативную память. Обработка идёт по одной странице.

## Проверка и пределы

Тесты проверяют автоматический подбор страницы без ручного выбора, русские формы запроса к английскому источнику, сохранение сносок, выбор изображения без подписи, частичное покрытие/возобновление, координаты PDF-изображений и блокировку выдуманных ссылок. В браузере дополнительно проверяются реальные локальные модели и автоматический выбор.

Это проверка работоспособности конвейера, не медицинская валидация Harrison/Sanford. Фактические файлы этих руководств в браузере пользователя не проверялись. PDF с необычной версткой, очень мелкими изображениями, сложными многостраничными таблицами или плохим OCR требуют сверки оригинала. Модель должна обозначать отсутствующие продолжения таблиц и нечитаемый материал, а не достраивать его по памяти.
