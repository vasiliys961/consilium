# W4 — один срез до видимого описания

Основание: владелец открыл DICOM, выбрал один срез и не получил текста в поле «Описание». Дополнительно явно разрешён **один** платный запрос для демонстрации цепочки. Предыдущие разрешения на ЭКГ/рентген использованы; они не дают права на повтор.

## Причины и исправления

1. Родительский `/radiology` опрашивал здоровье дочернего Next-сервера каждые 2 секунды. При одном ответе `running=false` он удалял iframe из React-дерева. Холодная компиляция или временная задержка могли уничтожить выбранные настройки, локальную подготовку и состояние выполняющегося анализа, после чего врач снова видел начало подготовки. Однажды открытый iframe теперь сохраняется при отрицательных и неполных health-check; смена клинического случая по-прежнему создаёт новую явную сессию.
2. В `singleSliceTest` успешный платный ответ завершал обработку после записи `receipts`. `report` оставался пустым, поэтому редактируемое описание и `data-concilium-report` не появлялись. Теперь готовое описание собирается **из того же проверенного ответа**, включая структуры, локализацию, морфологию, отрицания, неопределённость и ограничения. Дополнительный Argon/Opus для формирования текста не вызывается. Проверяются точная локальная привязка и граница одного среза.
3. Выбор явного режима «один платный Gemini» сразу запускает только локальную подготовку; промежуточную кнопку «Подготовить один срез» больше нажимать не нужно. Платная отправка по-прежнему начинается после проверки точной копии и одного SEND.
4. Законченный исходно-привязанный текст автоматически передаётся через существующий локальный мост в поле родительского приложения; интерфейс прокручивается к описанию. Ручные правки и промежуточные ответы не отправляются таким событием. Иные случаи/материалы не получают старый результат.
5. В шлюзе запрашивается квитанция OpenRouter. Только настоящий числовой `usage.cost` передаётся в безопасный журнал как `billedUsd`; медицинский текст и изображения в журнал не попадают.

## Проверка

- Новые регрессии: медленные/отрицательные health-check после открытия, полный текст одного среза, отказ для чужого/отсутствующего источника, правильная передача подтверждённого списания без текста пациента.
- 1144 теста родителя прошли; типизация родителя и Radiology прошла, сборка родителя прошла. Первое выполнение Turbopack build в временном worktree остановлено из-за намеренно внешнего symlink зависимостей; отдельная webpack-сборка Radiology прошла, включая последний маршрут прямого подтверждения. Не выдавать ограничение окружения за дефект приложения или успешный Turbopack build.
- В реальном браузере после установки защиты родителя исходный один DICOM сохранился.
- Автоматическое нажатие кнопок текущего in-app окна недоступно: CUA возвращает недоступную цель, а доступ к нативному Codex запрещён самой средой. Это ограничение управления, не запрос ещё одного разрешения на оплату. Для финального нажатия в открытом окне может понадобиться действие владельца; повторно разрешать уже одобренный один запрос не нужно.

Результат реального платного запроса, точный расход, фактическую версию установленного кода и оставшиеся ограничения записывать только после наблюдения. До этого сквозная платная приёмка этого DICOM не объявляется успешной. Данные самого DICOM и медицинское описание не публиковать в GitHub, логах или тестах.

## Упрощение по прямому требованию владельца

Владелец подтвердил, что прежний экран с бюджетами, выбором модели, окнами и отдельной подготовкой непригоден для его одного DICOM. Для **одного изображения CT/MR** основной маршрут теперь использует маленькую оболочку над существующим первичным Argon: локальная подготовка точной обезличенной копии → один SEND → редактируемое описание и автоматический возврат в родительское поле. Формы последовательного объёмного анализа в этом маршруте не отображаются. Многофайловый маршрут сохранён отдельно.

Сервер принимает отдельное разрешение **на один платный вызов**, требует ровно один проверенный кадр и запрещает дополнительного читателя даже при конфликте. Повтор того же изображения на авторизованном локальном рабочем месте получает сохранённый ответ; уже отправленная неудачная/незавершённая попытка блокирует новую оплату на 10 минут. Идентичность привязана к точным проверенным пикселям и языку, а не к обновляющемуся сроку cookie или случайному packet ID. Новая регрессия с намеренным конфликтом подтверждает ровно один вызов и сохранение неопределённости.

Проверки после упрощения: 1144 теста родителя и 17 проверок существующего исполнителя изображений прошли; типизация дочернего приложения прошла. Реальная отправка загруженного владельцем DICOM ещё ожидает нажатия в его окне: автоматическое управление кнопками недоступно. Не утверждать наличие описания до получения настоящего ответа.

В Preview установлен `bd3d96503af6b02789ba2a25ce86c963022472db` на отдельной ветке `chatgpt/codex-w4-direct-image-live-20261118`, порт 3207. Один исходный DICOM остался загружен после обновления. Локальная подготовка теперь открывается сразу при выборе одного CT/MR, без начальной кнопки, тестового переключателя и формы объёмного исследования. В реальном DOM видны готовая копия и единственная платная кнопка «Подтверждаю · получить описание (платно)». Основное поле описания пока пустое, в журнале нет `model.started`: оплаченный запрос ещё **не отправлялся**. Владелец уведомлён о необходимом физическом клике, поскольку CUA не может управлять этим окном. Не перезагружать окно с исходным файлом, не расходовать разрешение на другой материал, не объявлять сквозную приёмку завершённой.

CI Radiology для этого кода прошёл. CI родителя выявил ошибку изоляции проверок: импорт типа объёмной квитанции в новом родительском тесте затягивал зависимости дочернего приложения, отсутствующие в отдельной установке родителя. Дополнительно исправлена видимость подтверждения одного снимка: готовая локальная копия один раз прокручивается в видимую область.
