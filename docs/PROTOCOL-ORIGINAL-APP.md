# Полное приложение протокола внутри Concilium

Основной вход `/protocol` теперь встраивает исходное отдельное приложение «Протокол осмотра» целиком. Предыдущий компактный редактор сохранён на `/protocol/structured`.

## Русская версия

Исходник: `/Users/maxmobiles.ru/Desktop/протокол осмотра`, локальная ревизия `670a64c5ab191d455a8160c70c55a7e6ab23f1bb`. Взяты текущие файлы, включая авторские изменения после этой ревизии. Хеши исходных файлов сохранены в `integrations/protocol/ru/SOURCE.json`. Исходная папка не изменялась.

В собственной копии сохранены исходные страницы, компоненты, шаблоны, голосовой ввод, загрузка аудио и документов, персональная библиотека/RAG, рецептурный редактор, проверка взаимодействий, потоковый ответ, выбор модели и экспорты. Коричневая палитра и композиция не перерабатывались. Шрифты перенесены из локального кэша исходного приложения, чтобы сборка не требовала загрузки с Google. Секреты, исходная история Git, `.next` и пользовательские документы не копировались. Установленные зависимости используются через ссылку на исходный `node_modules`.

Собственная служба запускается на `127.0.0.1:3111`, автоматически при входе в модуль. Собранная копия запускается в production-режиме; без готовой сборки используется dev. Внешние модельные запросы выполняются только по действиям врача в исходном интерфейсе. Серверная конфигурация читается из существующей исходной установки и окружения Concilium, ключи не попадают в iframe.

Изменения для совместимости:

- импорт контекста и последнего сохранённого протокола выбранной карточки;
- явная кнопка передачи отредактированного документа обратно в карточку;
- проверка точного origin, окна-отправителя, идентификатора сеанса и предела размера, без текста пациента в URL;
- встроенная копия не подставляет старый несвязанный черновик из `window.name`, URL или localStorage;
- повторное сохранение одного документа обновляет эту версию, новый сеанс создаёт отдельную версию;
- смена карточки/версии создаёт новый сеанс; во время генерации переключение блокируется;
- исходное приложение получает системное правило не выдумывать нормальный осмотр, измерения, назначения и согласие; клинические предложения отделяются от документированных фактов;
- выбранный врачом провайдер теперь используется первым, а другой остаётся резервным;
- исправлено существующее несоответствие: кнопка GPT-6.1 Sol использовала старый идентификатор GPT-5.4;
- безопасные серверные квитанции вызовов попадают в общий `npm run logs`: модель, провайдер, статусы, токены, длительность, расчётная стоимость для известных тарифов. Тексты запросов и ответов туда не передаются. Внешняя медицина не тестируется платными запросами без разрешения.

Первичная сборка полной русской копии выполнена успешно. Тесты моста проверяют перенос полного текста, неизменность идентификатора, отсечение чужой сессии, ошибок и превышения размера. Отдельный тест исходного серверного транспорта с подставленными JSON/SSE-ответами проверяет, что поток не меняется, правило фактов добавляется, а содержимое случая не попадает в квитанции.

## Многоязычная версия Doctor Opus Global

После уточнения владельца источником английской/международной версии выбран материнский репозиторий `vasiliys961/doctor-opus-global`, ревизия `e6cc734d70d553b20bfcf535cf651e77b2386af9`. Пустая локальная папка английского протокола не используется как источник.

В `integrations/protocol/en` перенесены собственная страница протокола, исходные обработчики `protocol`, `dialogue-draft`, `diagnostic-report`, `final-note` и полный транзитивный набор библиотек. Хеши исходных файлов — в `SOURCE.json`. Платёжные аккаунты и сайт материнского приложения не изменялись. Для локальной расшифровки сделан отдельный loopback-обработчик с исходным AssemblyAI-провайдером и определением языка; он использует ключ локальной установки, без переноса серверной системы подписок сайта.

Это **самостоятельный движок**, а не перевод русского приложения:

1. Stage 1 — Diagnostic Reasoning Draft: 13 исходных разделов с гипотезами, недостающими сведениями и планом.
2. Дополнения врача — объективные данные, параметры осмотра, ROS.
3. Stage 2 — компактная SOAP-запись по исходным правилам Global. Её можно проверить и отредактировать.
4. Диагностические шаблоны исследований используют отдельный исходный Global-путь.

Промпты, наборы шаблонов, серверные маршруты, локальная RAG-библиотека, черновики и сохранённое состояние отделены от русской версии. Общими остаются клинический контекст выбранного случая, минимум требований к достоверности записи, механизм безопасной передачи документа и визуальный стиль. Рабочий черновик сохраняется с меткой `reasoning-draft`; SOAP — с `soap`. Оба состояния и дополнения врача сохраняются для продолжения работы. Карточка открывает последнюю запись **соответствующего движка**, а не последний протокол другой версии.

Модуль работает на `127.0.0.1:3112`. Используются выбранные серверные подключения Concilium; при настройке Polza её ключ сопоставляется с совместимой конфигурацией Global на сервере. Ключ не передаётся браузеру. Для AssemblyAI необходим соответствующий ключ; отсутствие ключа не выдаётся за успешную расшифровку.

Внешний вид взят из отдельного русского приложения: коричневая палитра, бумажное поле, serif-заголовки, боковая полоса и двухколоночная компоновка. Этапы и содержание Global сохранены. Добавлены недостающие переводы видимых настроек и моста для всех 10 языков: English, Español, Français, العربية, हिन्दी, Português, Bahasa Indonesia, Bahasa Melayu, Türkçe, 简体中文. Переключатель меняет интерфейс, язык последующих запросов и направление RTL; введённый текст не удаляется и не выдаётся за автоматически переведённый. Английские заголовки разделов сохраняются намеренно — это исходный контракт Global; содержание разделов задаётся выбранным языком.

Для ручной работы без запроса к модели добавлена возможность открыть редактируемый рабочий черновик из исходных заметок. Это не обозначается как результат модели. Внешние медицинские генерации для проверки новой интеграции не выполнялись.

## Локальная сборка

```sh
cd integrations/protocol/ru
npm run build
```

Затем основная сборка Concilium. При входе в `/protocol` собственная служба запускается автоматически. Для иной исходной установки используются `PROTOCOL_RU_SOURCE_HOME` / `PROTOCOL_EN_SOURCE_HOME`; они задают исходник серверной конфигурации. Сами приложения должны находиться в соответствующих каталогах `integrations/protocol/ru` и `en`.

Это интеграция существующего приложения, а не подтверждение медицинской точности всех его исходных алгоритмов. Отдельные функции речи, рецептной нормализации и взаимодействий продолжают использовать свои исходные серверные обработчики и требуют рабочих внешних подключений.

## Итоговая проверка

- Проверки основного проекта прошли; сборки Concilium и полной русской копии протокола успешны с проверкой TypeScript.
- В браузере оригинальное приложение открылось внутри выбранного синтетического случая. Контекст поступил в исходное левое поле, прежний протокол — в правый редактор. После ручной правки и нажатия кнопки передачи основная оболочка подтвердила сохранение в карточке.
- Ранее импортированный черновик не считается актуализированным автоматически: приложение показывает соответствующее пояснение. Повторное открытие цельного документа не добавляет новые обёрточные заголовки.
- SHA-256 всех 34 скопированных исходных файлов совпадает с начальным манифестом источника: исходная папка на рабочем столе не менялась. Изменения для интеграции находятся только в собственной копии Concilium.
- Медицинские генерации, расшифровка реальной речи и платные проверки взаимодействий в этой проверке не запускались. Их обработчики перенесены, транспорт проверен с подставленными ответами.

Проверка двух движков: 185 тестов основного проекта проходят, включая отсутствие смешения RU/Global, сохранение формата и этапов, десять полных UI-каталогов Global, исходные правила SOAP и язык содержания. Производственные сборки основного приложения и обоих модулей успешны. Готовность загрузки аудио отображается по наличию реального подключения AssemblyAI; при отсутствии ключа интерфейс не предлагает неработающую расшифровку. Диктовка средствами браузера остаётся отдельной возможностью.

Последние проверки: исходные заметки врача восстанавливаются из сохранённого снимка; отличающийся текущий контекст карточки предлагается добавить отдельно, без затирания текста. В Global локализованы и унаследованные подписи новых этапов, которые в материнском UI оставались английскими. Выбранная локаль хранится в памяти клиента и явно передаётся в API, поэтому язык обработки не зависит только от cookies вложенного окна. Автотест имитирует отказ cookies/localStorage. В браузере проверены ручной Global-черновик на французском интерфейсе, его отдельное сохранение и сохранность русского документа после переключения версий; генерации моделей при этом не запускались.

Global собирается отдельно командой `npm run build` в `integrations/protocol/en`. Оба готовых модуля запускаются автоматически при выборе в `/protocol`. В текущей установке health-маршрут Global возвращает `assemblyAi:false`; интерфейс показывает, что расшифровка аудиофайлов пока не настроена, вместо попытки записать и отправить файл. Проверка `x-opus-locale: ar` вернула `locale: ar` без cookies и вызовов моделей. Арабское направление интерфейса проверено в браузере; направление самих заметок определяется их текстом.

После перезагрузки браузер восстановил сохранённые английские исходные заметки и рабочий Global-документ; русский документ остался прежним. Интерфейс, включая названия этапов, проверен на французском и арабском; направление содержимого заметок остаётся корректным независимо от языка меню. Все 185 тестов прошли. Эти проверки не являются клинической валидацией моделей и не включали платную генерацию на медицинских случаях.

Защита редактора проверена реальной остановкой локального Global-сервиса: статус стал недоступным, но встроенное окно осталось смонтированным, несохранённая контрольная строка и фокус сохранились. После перезапуска службы редактор продолжил работу без перезагрузки. Обе службы RU/Global восстановлены; заключительная сборка Concilium прошла.

## Самостоятельный вход

На `/protocol` врач выбирает русский или Global и открывает выбранное приложение в отдельном окне. Клиническая карточка открывает этот же вход. Ранее сохранённые протоколы остаются в карточках. Для явной работы с ними доступен `/protocol/case`, который использует локальное хранилище случаев.
