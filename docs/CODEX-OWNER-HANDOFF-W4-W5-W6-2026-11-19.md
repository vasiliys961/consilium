# Codex: единая инструкция владельца Doctor Opus — W4/W5 → W6 (19.11.2026)

**Статус:** утверждённое владельцем направление и инструкция для последующей реализации; это **не** разрешение автоматически объединить PR, запустить платные модели или менять действующие серверы.  
**Репозиторий:** https://github.com/vasiliys961/consilium  
**Приоритет:** врачебная полезность, клиническая безопасность, сохранность случая и удобство интерфейса. Не количество PR, новых агентов или моделей.

## 0. Краткое окончательное решение владельца — исполнить именно так

**Clinical Standard = Claude Sonnet 5.5, рабочая лошадь для обычного разбора случая.**  
**Clinical Advanced = Claude Opus 5.5, подключается, когда случай выглядит сложным или высокорисковым; врач вправе выбрать Opus вручную.**  
**Extended Consilium = существующий много-ролевой консилиум, запускается ТОЛЬКО по явному запросу врача.** Система может объяснить, почему он полезен, но не должна автоматически запускать пять дорогих ролей.  
**Medical Vision / ECG / Radiology / US / детекторы = НЕ МЕНЯТЬ существующую схему.** Не переизобретать маршруты анализа изображений и не вводить обязательную новую ступень. Radiology остаётся отложенным долгом по текущему Roadmap.  
**Trial / Training (W6) = та же рабочая станция с Haiku 5.5**, переключаемая одной кнопкой, с общим предоплаченным балансом.

**НЕ ТРЕБУЕТСЯ** перед этим решением запускать Sonnet-vs-Opus, solo-vs-consilium, Vision A/B или иные новые клинические сравнения моделей. Владелец явным образом отказался от этого условия. **Обязательны обычные офлайн unit/integration/regression/CI-тесты корректности реализации.** Ни одного нового платного модельного вызова без отдельного разрешения.

Это новое продуктовое решение уточняет более ранние документы #102, #113, #119. Там, где прежняя формулировка предписывала обязательный полноценный консилиум или дополнительные платные A/B-тесты до такого маршрута, руководствоваться **этим решением**. Экспериментальные результаты не выдавать за медицинское доказательство преимуществ.

## 2. W4 — связность рабочего места, не дублировать код

**Ключевой принцип:** врач открыл случай → добавил данные → получил анализ → открыл существующий модуль → результат вернулся именно в этот случай → врач поправил → сохранил/напечатал → открыл снова. Без ручных портов и повторной загрузки документов.

- **#96:** большой стек W4 (162 файла) для Copilot, возвращаемых результатов, протоколов, генетики и защиты от устаревших асинхронных записей. Сначала сравнить с рабочим кодом. Переносить только нужное, не считать масштаб PR аргументом за полное слияние. Проверить зависимости #95 и пересечения с #93, #97, прежними casebook/protocol правками.
- **#103 → #109:** отдельный стек поиска рекомендаций; результат и его неизменённая/исправленная версия сохраняются в исходном случае, в том числе в зашифрованном переносимом архиве. Источник остаётся **неподтверждённым внешним материалом**, не врачебным наблюдением или одобренной терапией. Не дублировать уже существующие два поисковика и их adapter.
- **#99:** сохранить индивидуальные роли консилиума, особые мнения, несогласия и историю исправлений врача при экспорте. Отсутствующая роль = «НЕ ОЦЕНЕНО», не фиктивное согласие. Проверить конфликт файла lib/casebook.ts с #93/#96 и сериализацию вместе с #109.

- В integrations/protocol/en/lib/openrouter.ts и ru/lib/openrouter.ts **ещё записана Haiku 4.5**. Не заменять вслепую все строки: определить реальные функции. Для извлечения **уже произнесённых** фактов/форматирования переход на Haiku 5.5 выполнить, если конкретный маршрут ещё 4.5. Для **новых диагнозов и лечебных решений** использовать Clinical Standard Sonnet либо Advanced Opus, не маскировать клиническую интерпретацию под форматирование.
- **#105:** одобренная будущая политика прямого AssemblyAI STT-3.7: диктовка врача **без** диаризации, запись беседы с диаризацией; отдельный серверный API key; разделить STT-провайдер от общего OpenRouter-only правила для LLM. Существующий клиент AssemblyAI использует legacy speech_model=best и speaker_labels=true, поэтому требуются точечный аудит и адаптация, но **не активировать новые оплачиваемые маршруты сейчас**. - Акустические speaker A/B не гарантируют «врач/пациент». Аудиозапись и черновик должны переживать ошибку STT/LLM и навигацию; отсутствие надежного локального сохранения не обозначать как решённое. Только врач подтверждает протокол.
- Запрет на новые платные STT/LLM-тесты сохраняется; проверять контракт на mock/synthetic data.

## 6. W6 — новая утверждённая модельная политика, БЕЗ нового A/B исследования

Переход к этому этапу **после** W4/W5. Кодекс должен реализовать именно утверждённый маршрут, используя существующие функции, не переписывая систему с нуля.

| Функция | Основной путь | Когда изменить |
|---|---|---|
| Trial / Training | одна Claude Haiku 5.5 | Выбрано врачом одной кнопкой; учебный режим той же станции |
| Обычный разбор/врачебный вопрос | **Sonnet 5.5 по умолчанию** | Основной Clinical Standard |
| Сложный/высокорисковый клинический случай | **Opus 5.5** | Система определила объективные признаки сложности; врач может выбрать её вручную |
| Полный Extended Consilium | **существующие роли и модели** | **Только после явного нажатия врачом**. Возможно рекомендация консилиума, но НИКАКОГО автоматического запуска |
| Изображения, ЭКГ, Radiology, US, детекторы | **БЕЗ ИЗМЕНЕНИЙ** | Существующие маршруты, модели, порядок обработки, независимый второй просмотр по прежней логике |

### Признаки выбора Opus

Использовать уже доступный структурированный клинический контекст, текущие признаки опасности и существующие механизмы (не писать отдельный «умный» роутер, если он не нужен). Потенциальные основания: жизненно опасное состояние, неопределённость диагноза при высокой цене ошибки, противоречия важных данных, несколько взаимодействующих органов, значимые лекарственные противопоказания/полипрагмазия, беременность, дети, тяжёлая почечная/печёночная недостаточность, нестабильная гемодинамика, явный запрос на подробный сложный разбор. **Короткий текст не значит простой**: например, K 6.8 mmol/L, QTc 610 ms, боль в груди с признаками нестабильности.

Для неопределённых сигналов показывать причину и давать врачу понятный контроль выбора, не заставлять подтверждать одно и то же действие несколько раз. Sonnet остаётся обычным default. Не считать LLM self-confidence клиническим валидатором. Показывать фактически использованную модель, метку режима, цену/оценку и причину эскалации. Если Opus недоступна, не выдавать тихий Sonnet-подменный результат за выполненный Opus.

**Важно:** существующий lib/draft.ts исторически выбирает Opus первичной моделью, Sonnet — fallback. Не путать fallback с новым **осознанным выбором Sonnet по умолчанию**. Сохранить совместимость old casebook/existing specialty routes. Изменение маршрута не должно незаметно активировать Consilium.

### Trial/Training (согласованные #113 и #119)

- Одна рабочая станция, одни случаи, тот же интерфейс и последовательность действий, один общий **предоплаченный** баланс, один переключатель Trial ↔ Clinical, переход в обе стороны без потерь.
- Основная LLM Trial — только Haiku 5.5. Никаких скрытых вызовов Sonnet/Opus/Gemini. Учебные роли консилиума одной Haiku могут быть показаны **по выбору врача** как разные перспективы одной модели, **не** пять независимых экспертов. Для клинических функций с непроверенной безопасностью показывать учебный статус и необходимость врачебной проверки.
- Не ограничивать искусственно длину завершённого ответа ради копеечной экономии, но сохранять API max, лимит баланса, контроль повторов и запрет неизвестного дорогого fallback.
- **Изображения не переделывать ради Trial.** Не перенаправлять действующие Argon/Flash/Opus Vision-маршруты на Haiku и не обещать эквивалентную картинку. Интерфейс изображения/учебные примеры могут оставаться доступными; если действие требует не-Haiku платного анализа, объяснить границу Trial и потребовать явного выбора Clinical Pro, не включать чужую модель скрытно.
- При выходе из Trial не объявлять старое учебное заключение клинически валидированным.
- В PR #119 уже есть подробная спецификация Trial; #113 — ранняя идея. **Не создавать две разные реализации.**

## 8. Критерий конечного результата

Врач без технических настроек может создать/продолжить случай, ввести голос/текст/документ, получить содержательный разбор Sonnet либо Opus по сложности, запросить полный Consilium при необходимости, посмотреть сохраняемые отдельные мнения, проверить назначения и источники, сформировать редактируемый протокол и открыть тот же случай после перезапуска; прежние маршруты визуальных исследований работают **без изменений**. Учебный Trial — та же станция с Haiku 5.5 и явной маркировкой.

**Главный принцип:** простая надёжная станция с управляемой сложностью; сильная модель при сложном случае, Consilium по воле врача, изображения сохраняем. Никаких новых платных экспериментов для принятого решения.
