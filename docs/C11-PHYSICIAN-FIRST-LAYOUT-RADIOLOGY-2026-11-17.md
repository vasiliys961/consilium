# C11 · Рабочее место врача: широкие формы и модуль Radiology (17.11.2026)

## Обоснование

Отзывы врача при тестировании Preview на 3207: правая колонка с инструкцией по хранению повторяет информацию Copilot и занимает место; середина случая слишком узкая, в «Спросить специалиста» и библиотеке большие пустые поля и недостаточно удобный размер текста; подробности LLM и функция «критик» отвлекают от клинического ответа. При открытии Radiology возникает «пока недоступен», хотя **исходная Radiology пользователя работала на Mac**.

## Изменения

- Рабочая поверхность случая получает всю ширину; постоянная правая колонка с памяткой по хранению и WorkflowGuide убрана. Существующие **Copilot**, контекстная «Инструкция для врача», функции хранения и экспорт/резервные копии остаются.
- Ширина диалога специалиста — до 1560px, библиотеки — до 1600px. Текст и элементы ввода увеличены без потери мобильной адаптивности.
- Первым показан **клинический результат**; мнения по профилям и сведения о фактически задействованных моделях открываются только по запросу. Не скрывать предупреждение о незавершённых ответах и статус черновика.
- Ранее добавленный предварительный состав моделей консилиума также раскрывается в технических сведениях. Врачу доступны выбранные клинические профили без списка провайдеров.
- Radiology: встроенная копия (локальный порт Preview **3210**) отличается от ранее работавшего **самостоятельного Opus Radiology**. Зависимости исходного приложения не переиспользуются автоматически и не устанавливаются командой `npm run update:preview`. Это предотвращает вмешательство в оригинальный проект.
- Проверка статуса теперь сообщает, отсутствуют ли исходники моста, его отдельные зависимости или запуск неуспешен, вместо общей ошибки.
- Только при желании врача и **после остановки 3207** есть отдельная команда `npm run setup:radiology:preview`: она запускает `npm ci --ignore-scripts --no-audit --no-fund` только в `integrations/radiology/web` Preview; может потребоваться значительное свободное место. Не трогает домашний проект или 3107/3110.
- Если исходное приложение уже работает, администратор может *явно* задать `RADIOLOGY_STANDALONE_URL=http://127.0.0.1:<ФАКТИЧЕСКИЙ_ПОРТ>/` для ссылки «Открыть исходный Radiology отдельно». Это **отдельное окно без автоматической передачи данных случая** и не эквивалент встроенному мосту. Порт пользователя не угадывается, URL без loopback отклоняется.

## Ограничения и проверка

Разработка, статические проверки и CI не подтверждают, что **локальный Mac** уже имеет зависимости моста или может одновременно запускать два Next.js-процесса. Нужна проверка в Safari после установки отдельных зависимостей, если она действительно необходима. Не пересоздавать исходное приложение; не перезаписывать его `.env.local`. Обработка DICOM через интеграцию и клиническая точность — отдельные проверки.

**Не менять main, 3107 и оригинальный Opus Radiology.** Пользовательские данные сохраняются на прежнем origin Preview 127.0.0.1:3207.
