# Opus Copilot: экономичный координатор существующей станции

18.11.2026. Дополнение к W4 → W5 по запросу владельца; не новый проект, не Integration Hub. **В этом PR только оценка, воспроизводимый бесплатный прогон и предложение.** Рабочая модель Copilot, клинические модели, API, исполнители и интерфейс не переключены. Новых платных вызовов нет.

## Решение для следующего этапа

Полноценная ограниченная координация возможна в нынешней архитектуре. Первым кандидатом для будущего платного пилота предлагается **`openai/gpt-6-luna`**; второй кандидат — **`anthropic/claude-haiku-5.5`**. Цена у них одинаковая; опубликованный показатель задач автоматизации у Luna выше, а стандартные эндпойнты Haiku быстрее по опубликованной задержке. Это предварительный инженерный выбор, **не доказательство превосходства на врачебных запросах Doctor Opus**.

Сейчас нельзя честно назвать победителя по точности, языку, задержке или числу лишних действий на наших задачах: ни одну из сравниваемых моделей мы не запускали. Синтетические ответы ниже написаны вручную и проверяют наш контур, а не качество LLM. После завершения текущего W4 и отдельного разрешения нужен небольшой слепой пилот Luna/Haiku на одном наборе.

## Инструменты, качество и скорость

Публичные страницы OpenRouter на момент просмотра показывали для стандартных эндпойнтов:

| Модель | Опубликованная задержка провайдеров | Опубликованная генерация |
|---|---|---|
| Haiku 5.5 | примерно 0.89–2.79 с | 146–163 токенов/с |
| Luna | примерно 1.21–2.72 с | 67–139 токенов/с |
| Gemini 3.8 Flash | примерно 2.57–2.67 с | 73–76 токенов/с |
| Gemini 3.1 Flash Lite GA | примерно 0.68–0.83 с | 131–152 токенов/с |
| Gemini 2.5 Flash Lite | примерно 0.49 с | 188 токенов/с |

Это изменчивые опубликованные наблюдения разных провайдеров, **не замеры Doctor Opus и не гарантия полного времени врачебной задачи**. Не складывать их с искусственным «нашим» временем модели и не переносить на большие снимки или рассуждение.

На страницах моделей приведён один общий опубликованный AutomationBench-AA в режиме High: Luna 47.8%, Haiku 33.7%, Gemini 3.8 Flash 59.9%. На общем Intelligence Index картина другая: соответственно 21.4, 29.9, 30.8. Эти данные помогают выбрать кандидатов, но не измеряют выбор наших модулей, русский язык, сохранение в случай или безопасность клинического решения. Нельзя смешивать разные версии τ-bench и выдавать это за наше сравнительное испытание.

Источники этих чисел: страницы [Luna](https://openrouter.ai/openai/gpt-6-luna), [Haiku](https://openrouter.ai/anthropic/claude-haiku-5.5), [Flash 3.8](https://openrouter.ai/google/gemini-3.8-flash), [Flash Lite GA 3.1](https://openrouter.ai/google/gemini-3.1-flash-lite), [Flash Lite 2.5](https://openrouter.ai/google/gemini-2.5-flash-lite). Преимущество Luna для координации — **предположение для проверки**, а не подтверждённая локальная оценка качества.

Важная совместимость: по [официальной документации OpenAI](https://developers.openai.com/api/docs/models/gpt-6-luna) нативные function calls Luna в Chat Completions допустимы только с `reasoning_effort=none`; рассуждение вместе с инструментами требует Responses. При этом текущий `complete()` Doctor Opus всегда добавляет `temperature`, кроме одного другого семейства; в каталоге Luna и Haiku этот параметр не объявлен. **Простая подстановка ID модели недостаточна.** Нельзя ради этого переводить всё приложение на другой API.

Минимальная первая версия может запрашивать строгий JSON-план через существующий OpenRouter gateway, без нативного циклического tool calling. Реальные действия выполняет код Doctor Opus по проверенному плану. Такой подход переиспользует текущий механизм `reply/tools`, не требует Responses, SDK агентов, MCP, Eve или новой платформы. Правила [OpenRouter для structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs) и [client tools](https://openrouter.ai/docs/guides/features/tool-calling) требуют различать предложение модели и фактическое выполнение приложением.

## Что показал бесплатный прогон

Запуск:

```sh
node --require ./scripts/openrouter-only.cjs --experimental-strip-types scripts/evaluate-copilot-offline.ts --output=docs/fixtures/copilot-offline-results-2026-11-18.json
```

Исходные задачи: [18 синтетических запросов](fixtures/copilot-coordinator-tasks.json). [Полный результат](fixtures/copilot-offline-results-2026-11-18.json).

- Набор инструментов совпал с ожидаемым в **13/18** локальных маршрутах; явное открытие сработало в **8/11** запросах навигации.
- Обнаружены конкретные пробелы текущих правил: русское «Открой документы», прямое открытие русского рентгена/английской radiology, порядок «сначала лекарства, затем ЭКГ», неподдерживаемый Hub и просьба удалить всё. Последние не выполняют опасного действия, но получают неудачное предложение клинического разбора вместо ясного отказа/уточнения.
- 5 вручную составленных проверок парсера подтвердили ограничение списка модулей и отклонение неверных структур/слишком длинного ответа. URL, удаление, изменение настроек и Hub не превращаются в исполняемые инструменты.
- 5 искусственных сценариев транспорта: корректный ответ, неправильный JSON, 503, 402, исключение сети. Во всех — один stub-вызов, без автоматических повторов; при ошибке возвращается бесплатный локальный маршрут.
- Реальных сетевых и платных вызовов **0**. Возможность последовательного выполнения и записи результатов этим прогоном **не подтверждается**: существующий Copilot пока навигатор, и это его честная граница.

## Минимальные изменения после текущих задач W4

1. **Сохранить бесплатный первый проход** `physician-task-router`, `copilotRequestedOpen`, существующий интерфейс и передачу ID случая. Исправить найденные простые команды локально, не расходовать LLM на навигацию.
2. **Расширить нынешний JSON-план** в `physician-agent.ts`: максимум 4 шага из существующего каталога, явные зависимости, короткий вопрос только при необходимом недостающем материале. Выбор case ID, файлов, URL, модели и бюджета остаётся у приложения, а не у текста LLM.
3. **Добавить маленький контроллер выполнения в существующий поток Copilot**, не платформу: открыть/подготовить → вызвать существующий модуль → дождаться подтверждённого результата → атомарно сохранить в захваченный случай. Использовать имеющиеся API и возврат протоколов/ECG/Radiology/генетики. УЗИ и неподтверждённые модули не рекламировать как действующие инструменты. Учесть отдельные PR #84, #86–#88 до включения зависимых маршрутов; они пока не слиты.
4. **Привязать одно осмысленное подтверждение к плану**: врач видит действия, передаваемые материалы и предел стоимости и нажимает «Выполнить». Внутри той же подтверждённой операции нет новых технических галочек. Свободная навигация не требует подтверждения; микрофон, новая передача других данных/новому получателю, подпись/назначение, удаление требуют своего действительно необходимого действия. Изменение плана, материалов или случая делает прежнее разрешение непригодным.
5. **Ограничить задачу**: по умолчанию один запрос координатора; второй только для действительно необходимой переоценки уже полученного результата, в пределах того же заранее одобренного бюджета. Максимум 2 запроса, 6000 входных + 800 всех выходных токенов на запрос, 4 шага, один активный исполнитель, 20 с на планирование, 0 автоматических повторов/платных fallback. Предложенный потолок координатора $0.005 на задачу; по обычному тарифу Luna/Haiku максимальные 12000/1600 токенов дают оценку $0.002. Клинические вызовы имеют **отдельный совокупный предел**, включённый в разрешение, а не скрываются в дешёвой цене координатора. До реализации жёсткой проверки тарифов, размера входа и резервирования бюджета это только проект ограничений, не гарантия API.
6. **Использовать строгие квитанции действий**: LLM не пишет «сохранено», если приложением не подтверждена запись; сохранять только законченный проверенный результат. Для late response, смены случая, отмены, закрытого случая и повторного нажатия — изоляция/идемпотентность. Контекст старого случая и свободный текст из файлов не могут выдать новое разрешение. При ошибке — имеющиеся материалы и бесплатный маршрут, без бесконечного агентного цикла.
7. **Сохранить клиническую роль текущих специалистов**: интерпретация, дифференциальная диагностика, назначения и консилиум остаются в нынешних моделях. Координатор не назначает лечение, не делает диагноз, не подписывает протокол и не заменяет проверку врача.

## Приёмка и место в очереди

Сначала завершить текущие W4-маршруты станции и устойчивое сохранение результатов. Затем небольшие изменения выше в самостоятельном PR, бесплатные контрактные проверки и W5: выбранный модуль → фактический ответ → тот же случай → повторное открытие, смена случая в ожидании, отмена, отсутствие ключа/модуля, обрыв, исчерпанный лимит. Только после отдельного разрешения — одинаковые синтетические задачи Luna/Haiku с оценкой точности маршрута, зависимостей, лишних шагов, русского/английского, p50/p95, токенов и `usage.cost`. Не сравнивать модель по самодельным ответам и не переключать рабочий Copilot по рекламному описанию.
