# Concilium: единый механизм помощи врачу

## Цель и границы

Цель — полезная диагностическая и лечебная поддержка с проверяемыми источниками и наблюдением в динамике. Превосходство над другими продуктами — проверяемая гипотеза, а не свойство, получаемое от подключения нескольких моделей. Клинической валидации этой версии пока нет.

## Исполнение

1. **Транспорт** (`app/api/v1/cases/route.ts`) проверяет структуру и размер запроса, очередь и срок исполнения. Он не содержит клинической логики.
2. **Оркестрация** (`lib/analyze-case.ts`, `lib/case-plan.ts`) различает чтение материала, клиническое рассуждение, лечебную тактику и поиск доказательств. Автоматический выбор можно переопределить врачу.
3. **Подготовка** (`lib/intake-server.ts`, `lib/media-intake.ts`) превращает доступные форматы в текст, кадры и поддерживаемый сигнал. У источников сохраняются имя, хеш и ограничения охвата. Дубликаты имён получают разные внутренние обозначения.
4. **Проверка приватности** — локальное OCR и маски. Неудачная проверка не маскируется под «плохое медицинское изображение»: причина показывается явно. Необработанные изображения не отправляются.
5. **Профильные адаптеры** — цифровая ЭКГ, визуальный разбор ЭКГ/снимков, УЗИ, кожа/гистология, документы, лаборатория, генетика/CPIC и речь. Существование адаптера не означает доступность внешних весов.
6. **Согласование доказательств** (`lib/evidence-state.ts`) обновляет статус файла по фактическому ответу. Чтение пикселей не объявляется анализом цифрового сигнала; неизвестное не превращается в норму.
7. **Источники** — публичный поиск только для подходящей задачи, с фильтром темы, плюс отдельная библиотека врача (`lib/local-rag.ts`). Фрагменты библиотеки имеют стабильный ключ и текстовый локатор. Литературные документы не смешиваются с данными пациента. Заголовок статьи не считается прочитанным доказательством; абстракт и текстовый фрагмент явно различаются.
8. **Ответ** — для простого изображения сохраняется завершённая профильная интерпретация без второго шаблонного пересказа. Смешанные данные поступают в общий разбор. Диагностический/лечебный результат имеет структурированный контракт: факты, гипотезы и доводы, обследования с обоснованием, условные варианты ведения, проверки до назначения, вопросы, контроль и ограничения.
9. **Консилиум** вызывается по выбору врача, а не только потому, что загружены два формата. Он сохраняет разногласия и не изменяет исходные наблюдения.
10. **Помощник случая** (`lib/workflow-guide.ts`) ведёт по этапам на основании реального состояния: собрать данные, исправить вход, проверить результат, записать решение и динамику. Это организация работы, не автономное назначение терапии.

## Что исправлено в цепочке

- Нумерованные имена `ecg2.png`, `ekg12.jpg`, `ЭКГ2.png` распознаются как лист ЭКГ.
- Отсутствие цифровых отсчётов больше не запрещает предварительную визуальную интерпретацию фотографии.
- Обрезанный JSON не принимается за клинический текст. Есть ограниченный повтор с увеличенным выходным бюджетом; после неудачи показывается причина.
- Визуальная интерпретация не обрезается до 500 знаков.
- Калибровка ЭКГ не выдаётся за клинические находки «25 мм» и «10 мм».
- Статус «не прочитано» снимается только после реального чтения.
- Вопрос «что здесь» не отправляется в поиск литературы.
- Нерелевантные статьи отбрасываются по теме; классификация WHO не маркируется автоматически мировым руководством.
- Результаты детектора не используются как словарь, стирающий клинические гипотезы из другого источника.
- Текст документа и лабораторные значения сохраняются отдельно; regex больше не удаляет целые клинические предложения. Несовпадение цитируемого числа становится предупреждением.
- Оценка расходов учитывает полученные ответы модели, включая обрезанные попытки. Тарифы остаются оценочными.

## Форматы и фактический охват

| Вход | Реализованный путь | Ограничение |
|---|---|---|
| JPEG/PNG/WebP, декодируемые браузером HEIC/HEIF | Подготовка JPEG, локальное OCR, профильная интерпретация | До 2400 px по длинной стороне; неподдерживаемый декодер даёт явную ошибку |
| PDF | Локальный `pdftotext`, собственный извлекатель; для скана/ЭКГ — локальный `pdftoppm` | Визуально первые до 3 страниц; остальное не считается просмотренным |
| DOCX/TXT/MD | Извлечение текста | Старый `.doc` не поддерживается |
| XLSX/CSV/XML/JSON | Табличные/текстовые адаптеры | Старый `.xls` не поддерживается; лабораторный CSV не должен становиться ЭКГ |
| EDF/MAT/SCP/ECG XML и waveform DICOM | Имеющиеся парсеры и ECGFounder, если его исполнитель доступен | Закрытые форматы не считаются открытыми; недоступные веса не заменяются LLM-оценкой сигнала |
| DICOM/TIFF | Поддерживаемый несжатый одиночный кадр, затем визуальный разбор | Это не полная КТ/МРТ и не полноценная мультифреймовая станция |
| ZIP | Ограниченное раскрытие, затем общий конвейер | До 40 записей/12 МБ распакованных данных; вложенные архивы не раскрываются |
| VCF/VCF.GZ | Имеющийся генетический модуль | Нет вызова вариантов из FASTQ/BAM и анализа всех видов вариантов |
| Короткое аудио | Браузерный декодер → WAV → расшифровка → контекст врача | До 20 секунд; без успешной расшифровки нет фиктивного текста |
| MP4/MOV/WebM | 3 кадра с отметками времени → общий визуальный разбор | Выборочный обзор, не анализ всего движения, гемодинамики или функции |
| Камера телефона | Фотография/видеофайл через нативный выбор | Возможности камеры зависят от браузера и устройства |
| Микрофон телефона | Прямая запись при HTTPS; на HTTP — загрузка записи | Браузерные ограничения secure context не обходятся |

Общий бюджет визуального прохода — до 4 кадров на запрос. Остальные файлы сохраняют явный статус «не оценено». Отдельная Radiology-станция, тяжёлые детекторы и полный live-перевод не объявляются полностью перенесёнными.

## Смартфон

Главное приложение остаётся на loopback `127.0.0.1:3107`. По кнопке телефона запускается ограниченный LAN-вход на порту 3108: только страница передачи, статические файлы и загрузка по случайному токену. Клинические API и карточки через него недоступны. Токен находится во фрагменте QR-ссылки и убирается после открытия. Устройства должны находиться в одной сети; firewall может потребовать разрешить вход. Буфер ограничен 64 МБ, срок сессии — 12 часов. Это временная передача в памяти, не облачная синхронизация.

## Языки

Основное рабочее место имеет русский/английский интерфейс. Язык ответа выбирается отдельно из 11 языков существующего каталога. Материалы и вопрос могут отличаться по языку; исходные числа и текст сохраняются. Расширенная станция сохраняет 11 языков исходного интерфейса. Новые вспомогательные сообщения ещё не полностью локализованы на все языки. Локальный RAG пока лексический: межъязыковой поиск по библиотеке не гарантируется; нужны многоязычные эмбеддинги и отдельная оценка.

## Как использовать наработки внешних проектов

В `lib/module-catalog.ts` зафиксированы доступные адаптеры и реальные границы. Следующий перенос отдельных приложений должен передавать не свободный текст, а артефакт с идентификатором источника, методом, версией, охватом и ограничениями. Служба, которая не ответила или не имеет проверенных весов, остаётся недоступной. Из медицинского переводчика полезны уже перенесённые сверки доз/чисел/отрицаний; полный WebRTC-режим требует отдельной интеграции. Из Radiology-станции нужна передача выбранных кадров/окон и фактических ответов детекторов, а не обещание полного исследования по одной картинке.

## Внешние ориентиры

Официальное описание [Doximity Ask](https://technology.doximity.com/articles/doximity-ask) подчёркивает извлечение доказательств, реестр проверенных инструментов и клинические оценки по врачебным рубрикам. Это ориентиры для нашей архитектуры и методики проверки, не доказательство равенства или превосходства Concilium. [Описание клинического набора Doximity](https://blog.doximity.com/articles/introducing-the-doximity-clinical-ai-suite) также связывает ответы с документацией и другими врачебными сценариями. Копирования их закрытых моделей, библиотеки и независимой врачебной валидации здесь нет.

## Оценка

Автотесты проверяют маршрутизацию и сохранность данных, а не медицинскую точность. Синтетическая ЭКГ в `docs/qa/ecg2.png` — инженерный тест, не клинический бенчмарк. Для сравнения с мировыми аналогами нужен заранее зафиксированный набор публичных/разрешённых случаев, независимые экспертные эталоны, слепое оценивание безопасности, полноты, ссылок, времени и стоимости. Результаты публикуются вместе с ошибками и неопределёнными случаями.
