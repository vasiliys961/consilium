# C14 — интеграция существующих ambient-протоколов (первый безопасный этап)
**Дата:** 16 ноября 2026 года. **Ветка:** ChatGPT development, только PR в `chatgpt-dev`.

## Аудит исходного кода RU и Global

- В обеих копиях протоколов уже есть `AudioUpload`/MediaRecorder, необязательная браузерная диктовка, HTTP API `/api/transcribe`, исходная транскрипция в редакторе, `/api/protocol/dialogue-draft`, редактируемый черновик и протокол для возврата в тот же случай через `ConciliumProtocolBridge` и `GlobalCaseBridge`.
- RU использует OpenRouter speech adapter в локальном режиме. Модельная разметка Врач/Пациент (при включённом `STT_ROLE_DIARIZATION_ENABLED`) представляет собой **гипотезу по тексту**, не акустически доказанную роль. В исходной версии она рекомендовала выбирать наиболее вероятную роль; такой вывод не годится как достоверная медицинская атрибуция.
- Global использует AssemblyAI, если настроен; серверный `/api/transcribe` требует **отдельного согласия на передачу аудио**, связанного с SHA-256 конкретного файла (`nativeAudioGuard`). Проверка одной галочки UI не заменяет подписанный разрешающий артефакт. Поэтому наличие интерфейса не означает, что облачное STT уже работает в локальном Preview. Настройку внешнего провайдера и финансовые траты не делали.
- **Найденные риски:** прежний RU `autoStartOnMount` запускал микрофон при показе панели; RU и Global после получения транскрипта сразу вызывали модель для построения черновика. В Global при уничтожении компонента обработчик остановки также мог начать отправку оставшихся сегментов.

## Что исправлено, без переписывания протоколов

1. RU: удалена функция автозапуска микрофона. Микрофон включается только по кнопке внутри исходного аудиокомпонента; отмена/демонтаж компонента прекращает запись без загрузки.
2. Global: уход со страницы/уничтожение аудиокомпонента отменяет сегменты и прекращает запись без фоновой транскрипции.
3. Обе версии: запись/загрузка аудио в панели становятся доступны после явного подтверждения необходимого согласия; подтверждение не отменяет отдельную техническую проверку передачи/стоимости. После получения транскрипта **не запускается автоматически генерация черновика**: врач выбирает кнопку с предупреждением о внешней модели.
4. При подтверждённой передаче протокола в Consilium вместе с документом может возвращаться **исходная транскрипция как отдельные нумерованные фрагменты T1..Tn**. Разделение ролей маркируется `unverified`, временные метки не выдумываются; исходный клинический контекст и готовый текст не подменяются транскрипцией. Источник показывается в сохранённом случае при повторном открытии документа.
5. Изменение текста расшифровки влияет на версионирование документа: новая транскрипция сохраняется как новая редакция, даже если текст протокола не изменился.

## Что ещё НЕ реализовано и не должно считаться готовым

- Акустическая диаризация врач/пациент с независимой достоверностью, временные метки и связь **каждого** клинического факта (секции SOAP, препарата/дозы, отрицания) с исходным звуковым фрагментом. Сейчас сохраняются текстовые фрагменты, но факты ещё не имеют идентификатора подтверждающей реплики.
- Проверка полноты распознавания лекарств, доз, чисел, отрицаний и внесённых исправлений врача; врач должен сверять их с записью. Автоматический текстовый черновик не становится подписанным протоколом.
- Синтетический end-to-end тест браузера Preview 3207, Safari/Chrome, настоящий микрофон, фоновые сессии, работа STT/LLM и наличие корректной квитанции согласия/провайдера. Интеграции не запускали в этом PR.
- Согласованный механизм хранения/удаления реального аудио и контроль затрат. Аудио в случае через этот новый мост не сохраняется; транскрипция **может** содержать чувствительные данные, поэтому хранится только в текущем локальном случае, не отправляется в GitHub.
- Качество поддержки 10 языков Global и правильность перевода не валидированы.

## Критерии дальнейшего C14

Через отдельную браузерную приёмку с синтетическим приёмом проверить: согласие → запись → остановка → проверка транскрипции → явное создание черновика → правка → сохранение в текущий случай → повторное открытие текста с T1..Tn → история редакций. Затем ввести структурирование с **подтверждёнными ссылками fact-to-utterance**, обрабатывать пропуски/неуверенность и дозировки. Не задействовать Medical Translator как обязательный компонент ядра.

Остальные задачи `docs/ROADMAP.md`, особенно C12, сохраняют приоритет; C14 здесь **частично выполнен**, не клинически валидирован.
