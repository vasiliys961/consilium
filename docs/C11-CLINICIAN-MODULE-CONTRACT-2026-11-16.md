# C11 — единый врачебный сценарий модулей и безопасный возврат протокола

Дата: 16 ноября 2026. Цель: **врач не настраивает модули**. Один клик по модулю открывает готовое к работе окно, контекст выбранного случая уже передан, результат возвращается в тот же случай после подтверждения врача. Порт, npm, API-ключи, пути к весам и выбор движка не показывать как обязанности врача.

## Договор готовности каждого модуля (проверять отдельно)

1. **Подготовка** — при установке Doctor Opus администратор/инсталлятор подготавливает зависимости, необходимые модули и доступные веса. Если компонент требует отдельной лицензии, ключа, разрешения на передачу данных или большого скачивания, это однократная техническая подготовка, а не повторная процедура после клика. Нельзя молча скачивать или запускать тяжёлые модели на Mac с малой памятью.
2. **Открытие** — кнопка модуля определяет его готовность, при необходимости запускает уже установленную локальную службу, показывает понятный врачу статус. В Preview запуск протоколов RU/Global уже работает по словам врача. Отсутствующий модуль не следует выдавать за работающий; его установка/конфигурация пока не полностью автоматизирована.
3. **Контекст** — открытие из карточки передаёт ID, анамнез, исходный вопрос, уже доступные исследования и предварительный анализ; при смене случая либо языка несохранённое редактирование не теряется. Данные пациента не отправлять на сервер исключительно ради перехода между локальными компонентами.
4. **Возврат** — только подтверждённое действие врача добавляет документ в актуальную сохранённую карточку с точным ID случая, оригинальным источником, форматом, языком и временем. Запись не заменяет более свежие факты/решения врача. Повторное сохранение не создаёт дубликаты.
5. **Ошибки** — при отключении службы/сети или неуспешном сохранении текст остаётся в редакторе с ясным сообщением. Не трактовать временный сбой как отсутствие заболевания. Несовпадающие ID/язык, неподтверждённые данные и закрытый случай запрещают тихую запись.
6. **Проверка** — отдельно для протокола RU/Global, Radiology, генетики, переводчика и ЭКГ: открыть → передать синтетический случай → сохранить / отменить → переоткрыть → просмотреть оригинал, связи, историю. Сквозной тест в настоящем браузере обязателен до утверждения «полностью готово».

## Реализованная часть C11 — протокол RU/Global

- Ранее обработчик сообщения протокола читал `readCases()`, формировал новый объект и вызывал обычный `persistCase()`, что при параллельном автосохранении могло подменить более свежие данные. Теперь `persistNativeProtocol()` повторно читает текущую карточку **в сериализованной очереди записи** для конкретного случая и обновляет только поля протокола/его черновика.
- ID, язык и редакция проверяются перед сохранением. Для Global французский / английский и русский RU остаются разными документами. Несовпадение и закрытый случай отклоняются, текст не удаляется из отдельного редактора.
- Повторное поступление одного и того же документа по ID/содержимому — no-op. Если врач переписал документ с прежним ID, прежняя версия сохраняется в `protocolRevisions` и включается в Markdown-экспорт случая.
- История решений, прочие исследования, исходные файлы и черновики рабочего места не изменяются этим маршрутом. Синтетический тест эмулирует одновременное сохранение черновика карточки и возвращаемого протокола.
- Нет платных API или данных пациентов. Это проверка структуры сохранения, **не** клиническая валидация и **не** реальная браузерная приёмка.

## Открытые элементы

Нужно проверить на Mac в Preview 3207 полный вход из случая, передачу текста в оба редактора и сохранение документа обратно без потери состояния. Далее сквозная передача Radiology и переводчика; отсутствие дополнительных технических настроек для врача при установленном приложении должно проверяться как продуктовый критерий. Автоматическая первичная поставка тяжёлых сторонних модулей для чистой установки пока не реализована и не должна утверждаться.
