# C13 — первое единое окно врача (текстовый MVP)

Дата: 16 ноября 2026. Реализуется по действующему `docs/ROADMAP.md`, без замены остальных C-этапов.

## Работающий интерфейс

- На первом экране и внутри выбранного случая есть поле **«Чем Doctor Opus может вам помочь?»**.
- Текст задачи обрабатывается **локальным детерминированным маршрутизатором без LLM**: Radiology, ECG, УЗИ, VCF/генетика, лекарственная безопасность, рекомендации, клинический разбор, RU/Global протокол, запись беседы в готовом протоколе и документы.
- Для многоэтапного запроса (КТ + ЭКГ + разбор + протокол) показывается последовательность, краткое объяснение и отдельный переход в каждый готовый модуль. Не запускать «всё сразу» — врач подтверждает открытие каждого шага.
- Врач может явно перенести формулировку задачи в черновик клинического вопроса текущего случая: это не стартует платный разбор.
- При переходе из случая используется его существующий ID и штатный механизм сохранения черновика перед навигацией.
- Местный `/api/integrations` позволяет отделить установленный Radiology/протокол от отсутствующего. Статусы ECGFounder показываются как ограничение, а не ложное подтверждение полного анализа.
- Голос и микрофон не включаются, медицинские сведения не отправляются через маршрутизатор. Инструменты сами проверяют разрешение/стоимость медицинского анализа. Translator не обязателен.

## Проверки

`lib/physician-task-router.test.ts`: многомодульный клинический запрос, безопасность лекарств, запись приёма без автоматической транскрипции, текущий/новый случай, пустой/справочный запрос.

## Ограничения

Это **объясняющий навигатор**, не клинический LLM-агент. Он не может самостоятельно проверить медицинские гипотезы, корректность введённого текста, фактическую готовность всех внешних сервисов или завершённость многошагового процесса. Нет фоновой автономии и автоматической цепочки «выполнить все шаги». Браузерная приёмка Preview 3207 ещё нужна. Следующие улучшения: клинический контекст для планирования, подтверждённое получение результатов модулей и аккуратная голосовая навигация по согласованию.

C14 продолжает использовать исходные протоколы; ambient не считается завершённым только потому, что ссылка ведёт к форме аудиозаписи.

## Обновление C13 — 17 ноября 2026: первый экран и роли моделей

Установленная проблема интерфейса: `PhysicianTaskAssistant` уже был импортирован на главную `/` и `/workspace`, но располагался **после большого приветственного блока и метрик**, а предложения клинических задач были скрыты под `<details>`. Это объясняет, почему врач мог не увидеть помощника при первом открытии, даже если код C13 уже был в Preview. Другая возможная причина — локальная версия на Mac ещё не обновлена с `chatgpt-dev`, либо открыт порт 3107/`main` вместо 3207/Preview. Установить причину на конкретном Mac без проверки браузера нельзя.

Исправлено в отдельной feature-ветке:
- C13-помощник появляется **в верхней части главной страницы до приветственного блока**, остаётся на странице открытого случая, получает прямой пункт боковой навигации и три явных примера задач. Ничего не записывает, не запускает микрофон и не делает платных LLM-вызовов.
- На «Что умеет Doctor Opus?» и «Чем Doctor Opus может помочь?» показывает настоящий список доступных инструментов с переходами, а не только общий текст. Проверки наличия необязательных модулей сохраняются. Это **детерминированный навигатор по функциям**, не автономный медицинский чат-агент; полноценные сложные действия — отдельная следующая задача C13 после подтверждённой работы уже готовых связок.
- Глобальная панель «Gemini 4 Argon» переименована по смыслу в «ИИ-команда Doctor Opus» с раскрываемым пояснением. **Настройка Gemini не переключает Opus или GPT-6.1 Sol**. Роли сверены по существующим маршрутам: `CONSILIUM_ROLES` (Argon гипотеза, Sol план обследования, Opus критик/синтез, Sonnet безопасность), `CONSULT_MODELS` (Opus/Sol явный выбор) и `imageReviewRoute` (Argon основное изображение, Opus опциональное чтение по профилю/второму мнению). Не все модели вызываются на каждый вопрос.
- Инструмент `/consult` уже имеет отдельное меню Opus/Sol. Новая панель направляет туда, не создавая фиктивный общий переключатель моделей и не меняя бюджет/маршрутизацию.
- Из меню тарифов Gemini скрыт ненужный ценник Polza, поскольку интегрированный Doctor Opus работает в OpenRouter-only.
- Синтетические тесты проверяют размещение C13 до hero-экрана, маршруты без платных вызовов и соответствие видимых ролей действительным константам кода.

В раскрываемой «ИИ-команде» проверить, что Argon/Opus/Sol названы как разные роли, а не глобальный выбор одной модели.
