## Дополнение владельца · 18.11.2026

1. Использовать прилагаемое созданное изображение как визуальный образ Doctor Opus и референс персонажа.
2. Подготовить облегчённую 3D-модель с похожим лицом.
3. По умолчанию показывать небольшой аватар с возможностью разворачивать его.
4. Запускать анимацию только во время общения; вне диалога останавливать рендеринг и освобождать ненужные ресурсы.
5. Измерить плавность совместной работы с Consilium в браузере на **Mac M1 / 8 ГБ**. При заметном торможении автоматически переходить на **статичный портрет с голосом**.

Ориентир комфортной работы — **30 FPS**. Это целевой показатель, не подтверждённый результат: фактическую частоту кадров, задержки, память и влияние на основную станцию нужно измерить в браузере. Конкретный порог и механизм автоматического переключения определять по результатам испытаний.

Дополнение относится к этой отложенной идее; сейчас 3D, анимация и голосовой fallback не внедряются.

## Уточнение архитектуры владельца · 18.11.2026

- **Выделенный серверный GPU не использовать.** Copilot, голосовые сервисы и Cost Manager размещаются на CPU-сервере и используют внешние API там, где это требуется.
- Анимация и рендеринг аватара выполняются **в браузере через TalkingHead + HeadAudio**. Серверную генерацию или трансляцию синтезированного видеопотока не внедрять.
- Сохранить возможность подключить **собственную внешность Doctor Opus** после подготовки совместимой 3D-модели; смена персонажа не должна требовать переписывания голосовой или клинической логики.
- Существующая логика Consilium остаётся основой клинической работы. Аватар — опциональное представление уже работающего Copilot, без вмешательства в медицинские цепочки.
- Действующее ограничение приложения сохраняется: все LLM-вызовы только через OpenRouter, без Polza. Уточнение не разрешает новые платные вызовы, установку служб или запуск прототипа сейчас.
