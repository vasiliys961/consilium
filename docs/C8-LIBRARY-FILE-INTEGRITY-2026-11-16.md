# C8 — идентичность книги и актуальность файла в личной библиотеке

Дата: 16 ноября 2026. Новый этап после C7; целевая ветка `chatgpt-dev`, `main` не затрагивается.

## Практическая польза

- При импорте книги объёмом до **64 МБ** вычисляется SHA-256 **всего бинарного файла**. Уже импортированный полностью идентичный файл не создаёт новую книгу, не дублирует страницы и не запускает повторную векторизацию, даже если имя другое. Две редакции с разными байтами сохраняются раздельно, без молчаливой перезаписи.
- Для больших книг (до 250 МБ, как и прежде) импорт остаётся доступен, но полная проверка отпечатка пропускается, чтобы не увеличивать пиковую память на маломощном компьютере. Пользователь видит число файлов без такой проверки.
- Для книг с оригиналом в выбранной папке сохраняется размер и `lastModified` на момент импорта. При поиске по кандидату и просмотре книги приложение сверяет доступный оригинал с этими данными. Изменённый или недоступный оригинал **не должен** отдавать старый фрагмент или страницу как актуальный материал. В библиотеке показано, когда нужно повторно импортировать.
- В библиотеке выводится оценка занятого и доступного места через `navigator.storage.estimate()`. Это оценка хранилища *всего приложения в данном браузере*, а не точный размер индекса библиотеки.

## Границы

- Одинаковое название или похожие тексты **не** считаются тождеством книги. SHA-256 проверяется только для бинарно идентичных файлов до 64 МБ; иная PDF-компрессия, метаданные или текст той же книги в новом файле могут выглядеть как отдельная запись.
- Размер + дата изменения — **быстрая проверка версии**, а не криптографическое подтверждение актуального содержимого. Теоретически файл может поменяться без изменения этих метаданных; криптографическая проверка на каждом поисковом запросе не введена из-за затрат.
- Старые записи в папке без `sourceModifiedAt` помечаются «версия не проверена», но не уничтожаются и не исключаются автоматически из поиска. Для полной проверки их надо повторно импортировать.
- Отзыв доступа к папке или изменение файла не удаляют книгу и индекс: исключается выдача старого фрагмента; после повторного импорта врач может отдельно удалить прежнюю запись.
- При смене имён, одинаковом содержимом в разных изданиях PDF/текста и одновременном импорте из нескольких вкладок глобальная транзакционная дедупликация ещё не гарантирована.
- Сканированные книги и OCR, переносимый экспорт и восстановление индекса, проверка на реальных книгах остаются пунктами C8. Без независимой клинической проверки нельзя считать найденную страницу достаточным основанием назначения.

## Проверка

Синтетика: повторный импорт одной книги под другим именем, изменённая редакция, оригинал из папки без изменений, изменённый/недоступный оригинал и отсутствие его в результатах поиска. Дополнительно CI: весь `npm test`, TypeScript и Next.js build. Ручная проверка Safari/Chrome, разрешений File System Access и квот ещё не выполнена.
