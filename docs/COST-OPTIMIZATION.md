# Экономика клинического анализа — этап 1, без деградации качества

**Контрольная точка (15 ноября 2026):** первый синтетический случай с консилиумом фактически стоил $0.214 по сообщению владельца, прежний UI отображал $0.1336. Исправление чтения `usage.cost` уже включено в PR #3. Эти числа не доказывают стоимость любого следующего случая.

## Что сделано в этом PR

1. **Защита от случайной повторной оплаты.** Успешный завершённый разбор получает компактный fingerprint настроек (режим/вопрос/материалы/библиотечные источники/язык/запрос на второе мнение). При повторе точно того же состояния в рабочем интерфейсе врач увидит предупреждение и фактическую стоимость предыдущей операции (или помеченную оценочную сумму). Он может отказаться или намеренно повторить: запрос никогда не блокируется без возможности продолжить.
2. **Без потери источников.** Только полностью идентичные строчки цитат/фрагментов RAG убираются из повторяющегося контекста всех пяти консилиумных ролей. Разные доказательства, скептик, лекарственная безопасность и итоговый синтез остаются.
3. **Никаких дополнительных LLM, весов, Docker, серверных процессов, запросов OpenRouter или внешнего хранилища.**

## Что это НЕ означает

- Этот PR не доказывает снижения стоимости **первого** консилиума: при уникальных источниках длина промпта может остаться прежней.
- При новом клиническом факте, изменении режима, новых материалах, включении второго мнения или иных вариантах источников предупреждение не блокирует новую оценку. Наличие подтверждения само по себе не обещает того же качества новой генерации.
- Будущие оптимизации «меньше специалистов», «заменить Opus более дешёвой моделью» и «сжать медицинские данные» нельзя включать без парного качества/безопасности A/B на синтетических и разрешённых эталонных случаях.

## Следующие доказательные этапы

1. **Разметка расходов по модели и этапу** с использованием только безопасных метаданных OpenRouter: billed USD, входные и выходные токены, reasoning/retry, причина завершения.
2. **A/B базовая связка против экономного режима** на фиксированных врачебных сценариях: сердечная недостаточность/кардиоренальная дисфункция, безболевой ОКС, ТЭЛА, инсульт, ошибка лекарства, гиперкалиемия, а также простые безопасные вопросы. Врач вслепую оценивает фактические ошибки, пропуски, опасные назначения и клиническую пользу.
3. Только после неухудшения ключевых показателей включать адаптивные дорогие вызовы по сложности. Всегда сохранять проверку критических альтернатив и лекарственную безопасность.
4. Ввести **настраиваемый бюджет USD/случай** с оценкой до обращения, учётом всех повторов и объяснимым завершением при достижении лимита — без выдачи частичного ответа за окончательный.

## Инженерная проверка

`lib/repeat-analysis.test.ts` проверяет точное совпадение настроек, источников и клинического статуса; `lib/consilium.test.ts` — удаление только идентичных ссылок при сохранении всех пяти ролей. CI тестирует код, но клиническую безопасность экономного режима ещё нужно оценить отдельно. Синтетические испытания — без платных запросов.
