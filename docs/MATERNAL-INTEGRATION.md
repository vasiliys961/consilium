## Что подключено

1. **VCF/VCF.GZ.** Локальное извлечение видно сразу после загрузки. Таблица содержит все сохранённые вызовы, включая 0/0 и неполные генотипы, исходные INFO-аннотации и END референсных блоков gVCF. Отдельная таблица альтернативных аллелей и отдельная классификация ACMG. Отсутствие критериев не считается ошибкой чтения. Модель получает структурированный контекст с явным предупреждением об ограничении объёма; старый предел первых 30 вариантов снят. Сжатые VCF внутри ZIP также распаковываются; распаковка останавливается на пределе текста, без неограниченного раздувания.
2. **ECGFounder.** Исправлен ошибочный относительный путь: установленный движок на рабочем столе обнаруживается автоматически. `ECGFOUNDER_HOME`, `ECGFOUNDER_PYTHON`, `ECGFOUNDER_WEIGHTS` позволяют задать установку явно. Анализ цифрового сигнала и визуальное описание фотографии остаются различными путями. Нейросеть не применяется к фотографии как к исходному сигналу.
3. **Поток ответа.** Основной разбор и формирование протокола используют реальные SSE-дельты провайдера, этапы выполнения и финальный валидированный результат. Предварительный текст подписан; обрезанный поток не становится завершённым заключением. Старый JSON API совместим. Клинические дельты не записываются в терминальный журнал. Стоимость учитывает все полученные ответы, включая повторные попытки; отсутствие токенов отмечается как неполный расчёт.
4. **Медицинские изображения.** Выбор профиля: ЭКГ, рентген, КТ, МРТ, УЗИ, дерматоскопия, гистология, рана, маммография, глазное дно, эндоскопия. Подключены критерии материнского Opus и профиль ран. Контроль качества рассчитывается по фактическому растру, а не по фиктивным значениям. Профиль не превращает список критериев в находки и не выдаёт отсутствующие измерения, ИГХ или BI-RADS за известные сведения. Это профильное чтение мультимодальной моделью, а не новые обученные детекторы для каждой специальности.
5. **Полная станция Radiology.** `/radiology` запускает собственную копию станции на `127.0.0.1:3110`. Изоляция необходима из-за разных версий Next/React: основное приложение 14/18, исходная станция 16/19. Сохранены просмотр серий, MPR, исходные ограничения ресурсов, обезличивание и проверки реальной готовности детекторов. При запуске читается существующая серверная конфигурация источника; секреты не передаются браузеру. Врач передаёт подготовленное описание в выбранный случай отдельной кнопкой, затем сохраняет его. Мост проверяет источник окна, точный origin и идентификатор сессии. Смена карточки перезапускает сеанс исследования, исключая перенос старого описания другому пациенту. Контекст случая виден врачу внутри станции; автоматическое включение этого контекста во все внутренние алгоритмы исходной станции не заявляется.
6. **Протоколы.** `/protocol`: приём, кардиология, ЭКГ, лучевое исследование, УЗИ, эндоскопия. Источник — контекст, решение врача и последний разбор с сохранённой неопределённостью; устаревший разбор обозначается. Разделы можно редактировать и сохранять в IndexedDB случая, экспортировать настоящим DOCX. Сохраняется снимок обезличенного источника. Протокол не добавляет неизвестный осмотр, назначения или согласие.
7. **Журнал.** `npm run logs` показывает локальную проверку цифровой ЭКГ, основной разбор, протокол и безопасные квитанции вызовов моделей подключённой Radiology. Её шлюз передаёт только имена известных моделей, провайдера, статусы, токены и длительность через stdout управляемого процесса. Никаких сообщений, изображений или полей пациента в этом мосте нет.

## Проверки и границы

- Настоящий локальный запуск ECGFounder на синтетической 12-канальной записи 500 Гц, 5000 отсчётов: исполнитель прочитал запись, вернул 150 выходных классов. Это техническая проверка, не оценка медицинской точности.
- Пользовательский `test.vcf` проверен только локально: 902 записи, 902 сохранённых вызова, 114 альтернативных аллелей, 748 референсных вызовов, 0 ошибочных строк. Остальные вызовы не объявляются нормой. Генетические данные не отправлялись во внешние модели при проверке.
- Автотесты проверяют реальное разбиение SSE по байтам/UTF-8, обрыв потока, полный путь изображения к разбору, сохранение аннотаций VCF, ограничение GZIP, структуру протокола, запрет выдуманной нормы, изоляцию моста и отсутствие клинического текста в логах. Внешние ответы в этих тестах подставлены, а не оплачены.
- Внутренняя станция Radiology сохраняет собственный русский интерфейс; оболочка и новые инструкции включены в десять языков основного приложения. Полный перевод внутренних экранов исходной станции не выполнен.
- Веса и службы, которых нет или которые не запущены на компьютере, не обозначаются готовыми. Тяжёлые модели не устанавливались автоматически. Платный полный проход КТ/МРТ и клиническая точность новых профилей не проверены. Превосходство над другими системами не установлено.
- Обычный анализ одиночного DICOM в основной станции ограничен поддерживаемым кадром. Для серии используется полная Radiology. TIFF, видео и сканы PDF сохраняют обозначенные ограничения охвата; WSI, любые кодеки и каждый специализированный формат не заявляются поддержанными.

Для запуска основной станции: `npm run build`, затем `npm start`. Radiology запускается её кнопкой; её шлюз и терминальные квитанции активируются в управляемом приложением процессе. Исходная установка на рабочем столе нужна для установленных зависимостей ECG/Radiology; копия пока не является автономным установщиком для другого компьютера.

### Результаты итоговой проверки

Основное приложение: 175 тестов пройдены, производственная сборка успешна. Изолированный модуль Radiology: TypeScript и 5 тестов его изменённого шлюза пройдены. Через браузер реально сформирован синтетический протокол с помощью `openai/gpt-6.1-sol` / Polza; стоимость по полученным токенам около $0.004322. Документ не выдумал жалобы, осмотр, диагноз, назначения или согласие; сохранение в случай и восстановление после перезагрузки проверены. Этот вызов был единственным живым модельным запросом текущей итоговой браузерной проверки.

Отдельный платный тест потокового изображения автоматическая проверка исполнения отклонила: она требует явного разрешения на конкретный внешний платный вызов. Этот запрос не выполнялся и обход отказа не предпринимался. Транспорт изображения проверен модульным сквозным тестом с подставленным SSE-ответом; живой поток изображения остаётся непроверенным.

Автоматический запуск Radiology из производственной сборки через кнопку проверен: установка и служба готовы; исходный интерфейс `/viewer` реально отображается внутри Concilium. Передача контекста синтетического случая в мост подтверждена, отсутствие горизонтальной прокрутки оболочки проверено при ширине 1280 и 390. Снимки: `docs/qa/integrated-radiology.png`, `docs/qa/integrated-protocol.png`. Перенос готового заключения из реального исследования не проверялся: тестовые данные DICOM и платный анализ для этого не запускались.
