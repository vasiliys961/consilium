# Передача клинического разбора в существующий протокол: выбор языка

Дата: 15 ноября 2026. Повод: врач указал, что **сам клинический разбор сейчас не генерирует готовый протокол**, но отдельный русскоязычный и многоязычный модуль уже существуют. Не строить ещё один редактор, не заявлять автогенерацию.

## После клинического разбора

- Только после успешно **сохранённого** завершённого клинического анализа появляется компактный, закрываемый выбор: **Русский / English / другие языки и несколько версий**.
- Не завершённый или не сохранённый разбор не вызывает переход.
- Выбор языка формирует только внутренний URL на существующий путь app/protocol/case и не вызывает диагностические модели.
- При наличии несохранённых правок переход сначала сохраняет исходный случай; при ошибке сохранения переход блокируется.
- Создание самого протокола происходит **после перехода** в существующем отдельном приложении, по действию врача. Оно может использовать модель и стоить денег; это не бесплатный перевод и не новая оценка исходного DICOM/ЭКГ. Врач проверяет текст и сохраняет протокол в тот же локальный случай.

## Русская и многоязычная версия

- ru → исходное русское приложение; другие поддерживаемые языки → многоязычный Doctor Opus Global.
- В многоязычном плане врач видит выбранные языки и последовательно открывает соответствующие версии. Переключение не создаёт протокол само и не запускает повторный консилиум.
- protocolForEdition выбирает сохранённую версию **по фактическому locale**: французский черновик не подставляется в английский. Для отдельных незавершённых черновиков предусмотрены независимые записи protocolScratchByLocale в локальном хранилище.
- Прежний мост protocol→Concilium, проверка origin/session и оригинальные приложения сохранены. Новые серверы и процессы не добавляются.
- Перевод клинических данных и правильность протокола требуют проверки врачом. Создание двух языковых версий может требовать двух отдельных запросов самого модуля; независимое клиническое рассуждение при этом не повторяется автоматически.

## Проверка

Синтетические тесты: вход в существующий модуль с исходным идентификатором случая, поддержанные языки, корректное разделение версий, отсутствие скрытого маршрута на анализ. GitHub CI проверяет TypeScript, тесты и build, но **не** доказывает доступность и сквозное генерирование исходных дочерних приложений на Mac Preview.

После успешного CI обновить **только Preview 3207** и проверить: сохранённый синтетический случай → клинический анализ → панель языка → русская/английская/другая версия в Protocol → ручная генерация и сохранение → возвращение к случаю. main и Codex на 3107 не трогать.
