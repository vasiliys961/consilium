# C11 — возврат генетической консультации в клинический случай

Дата: 16 ноября 2026. Цель: работающие родительские модули без повторной загрузки, потери врачебной истории или неверной привязки вывода к изменённым материалам.

## Обнаруженные проблемы

1. В `app/genetics/page.tsx` консультация могла успешно завершиться **без новых файлов** (врач задаёт вопрос в контексте уже открытого случая), но кнопка сохранения оставалась выключенной: `!files.length`. Текст результата оставался только на странице.
2. После генетического разбора врач мог заменить VCF и сохранить прежний результат как относящийся к новому файлу. Ранее `save()` не сверял SHA входных файлов с SHA во время интерпретации.
3. Повторное нажатие сохранения создавало новый `analysis.id` даже для той же завершённой консультации.
4. Для уже прикреплённого к случаю VCF требовалось выбирать файл второй раз вручную.

## Реализованный врачебный сценарий

- Если в открытом случае уже есть VCF с текстом и валидным SHA-256, модуль предлагает кнопку **«Использовать VCF из случая»**. Нажатие только копирует ссылку на сохранённый материал в текущий интерфейс, не вызывает внешние модели.
- При генерации успешного заключения создаются идентификатор отдельной консультации, исходный набор SHA-256, ID выбранного случая и контекст/вопрос в момент запроса.
- Завершённую **консультацию без новых вложений** тоже можно сохранить в историю случая.
- Сохранение получает свежую запись `readCases()`, добавляет лишь новые файлы по SHA, включает заключение и источники/пасажные идентификаторы и не изменяет прежние анализы, события, решения и их правки.
- После изменения VCF по тому же имени прежнее заключение не сохраняется с новой версией: интерфейс предупреждает, нужен новый разбор. Отсутствие SHA блокирует утверждение идентичности файла.
- Повторное сохранение того же `analysis.id` — no-op, не создаёт двойные записи. Закрытый случай и попытка приписать результат другому ID отклоняются.

## Тесты и ограничения

Синтетические тесты проверяют точную привязку к файлу, повторное сохранение, сохранение истории решения и источников, перезагрузку из локального IndexedDB, продолжение разбора, несвязанный и закрытый случай. Без данных пациентов и платных API.
