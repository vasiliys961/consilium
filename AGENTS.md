# Настройки нынешнего приложения

- Все LLM-вызовы в этом приложении — только через OpenRouter. Polza AI здесь отключена: не использовать её для разбора, радиологии, ЭКГ, тестов, переводов интерфейса и запросов каталога.
- Не возвращать резервный переход на Polza при ошибке OpenRouter.
- Запускать сервер через npm scripts; дочерние интеграции — через адаптеры lib/*-integration*. В них установлен локальный режим OpenRouter-only. Сетевые Node-скрипты этого проекта запускать с `node --require ./scripts/openrouter-only.cjs ...`.
- Исходные самостоятельные приложения вне этого workspace (в частности на Desktop), их ключи и конфигурации не изменять. Настройка относится только к нынешнему приложению и запускаемым им интеграционным копиям.
- Не печатать ключи и содержимое .env.local. Не выдавать примерную оценку стоимости за квитанцию провайдера.

## Цель и границы разработки

- Обязательное стратегическое описание продукта: [docs/PRODUCT-VISION.md](docs/PRODUCT-VISION.md). **Главный критерий — врачебная полезность, ясность, безопасность, скорость и умеренная стоимость**, а не число LLM или объём кода.
- Повторно использовать проверенные исходные проекты Doctor Opus Global, Radiology, ECGFounder, ECG-ансамбли, US, GenomicsAI Pro и переводчик через отдельные адаптеры. Не переписывать работающие Radiology/ECGFounder без клинической или технической причины. Отделять факт работы исходного модуля от сквозной проверки в Preview.
- **Единый врачебный сценарий модулей:** врач нажимает модуль — уже установленный компонент открывается, получает текущий случай, выполняет работу и возвращает подтверждённый результат в ту же карточку. Не требовать от врача npm, установки пакетов, команд, портов, настройки моделей или повторной загрузки уже сохранённых материалов. Техническая подготовка выполняется при установке/администрировании, а не на каждом клике. Если модуль недоступен, показывать ясную причину на языке врача, сохранять черновики и не выдавать его за работающий. Критерий приёмки — сквозной сценарий «открыть → передать → обработать → сохранить → открыть снова», отдельно для каждого модуля. См. [C11 контракт модулей](docs/C11-CLINICIAN-MODULE-CONTRACT-2026-11-16.md).
- Держать ядро лёгким, сравнимым по нагрузке с существующими Opus. Тяжёлые CT/MRI/US-детекторы — модульно и по запросу; размещение на сервере допустимо только при достаточных ресурсах и разрешении владельца. Ни одна новая служба/веса не запускаются автоматически при старте приложения.
- Рабочая ветка Codex `main` и его экземпляр на 3107 не изменяются. Разработка ChatGPT — в отдельных ветках и draft PR к `chatgpt-dev`; локальный независимый Preview — 3207. Не выполнять merge, деплой и платные клинические вызовы без согласия.
- Для расширений сначала измерять пользу, ресурсную нагрузку, надежность, фактическую стоимость и клинические ошибки. CI/синтетические тесты не означают клиническую валидацию.
