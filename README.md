# Concilium — рабочее пространство Doctor Opus

Локальная исследовательская версия для обезличенных клинических случаев. Исходная копия: `~/Desktop/concilium`; новая рабочая копия: `~/Documents/ChatGPT/cosiliim`. Оригинал не изменён.

## Запуск

Node.js 22.18+ (тесты используют встроенную поддержку TypeScript).

```sh
npm install
npm run dev
```

Откройте http://127.0.0.1:3107. На главной сохранена прежняя зелёная панель; кнопка «Войти в рабочее пространство» открывает `/workspace` с инструкциями и карточками. Сохранённый случай с главной открывается сразу в рабочем пространстве. В текущем рабочем окружении зависимости подключены из исходной папки символической ссылкой. Для независимой установки удалите только ссылку `node_modules`, затем выполните `npm ci`.

Ключи находятся в игнорируемом `.env.local`; имена — в `.env.example`. Ключи исходной локальной установки перенесены в новую копию без вывода в журнал. Нынешнее приложение использует только OpenRouter. Polza отключена, в том числе как резервный шлюз. При запуске интеграций их окружение изолируется; исходные приложения и их настройки вне workspace не изменяются. Наличие ключа не гарантирует доступность модели или баланс. Тяжёлые детекторы требуют собственных служб; наличие интерфейса не означает, что установлены веса.

## Рабочий сценарий

1. Создать случай, указать обезличенный контекст и вопрос.
2. Добавить документы, таблицы, VCF или изображения. На основном экране действуют ограничения 8 МБ на файл и 12 МБ на совокупный JSON материалов.
3. Подтвердить отправку обезличенных данных внешнему шлюзу. Запустить разбор с консилиумом или без него.
4. Проверить черновик, источники, отдельные мнения и перечень неоценённых данных.
5. Зафиксировать решение врача и последующую динамику. Следующий разбор получает эти записи; прежние версии остаются в истории.
6. Нажать «Сохранить случай». Сохранение выполняется в IndexedDB текущего браузера и origin. Другой порт или браузер имеют отдельное хранилище. Для пробных обезличенных случаев пароль не нужен. Чтобы зашифровать сохранённые случаи, откройте «Хранение случаев» → «Включить пароль».
7. Экспорт Markdown содержит контекст, хронологию, версии разборов и источники. Это читаемый отчёт, не резервная копия бинарных материалов и не импортируемый архив.

`/workbench` сохраняет исходные расширенные инструменты. Выбор сохранённого случая переносит его контекст. Исследования загружаются в станции отдельно; кнопка сохранения возвращает результат в выбранную карточку. Для таких исследований в карточке сохраняются извлечённый текст, имя и хеш, но не все исходные бинарные данные. Оригиналы нужно хранить отдельно.

## Состояние реализации

- Главное рабочее место, поиск и список сохранённых случаев.
- Локальное хранение карточек и доступных материалов; ручное сохранение и предупреждение при выходе с изменениями.
- Диагностический/лечебный черновик через существующий серверный конвейер, отдельные мнения консилиума.
- История разборов с сохранением контекста каждой версии, динамика и решение врача.
- Статус получения клинического черновика отделён от факта вызова шлюза.
- Существующие специализированные пакеты сохранены. Их контракты проверяются тестами; это не клиническая валидация.
- Полная интеграция отдельных репозиториев Radiology, ECG и Genomics не завершена. Сохранённые в concilium адаптеры не равны полным приложениям этих проектов.

## Следующие этапы

1. Унифицировать специализированные станции через единый контракт артефактов, с передачей выделенных кадров/сигналов и явным охватом анализа.
2. Развить проверку привязки каждого клинического утверждения к полному тексту источника. Структурированные гипотезы и план уже реализованы; поисковая находка без текста не считается доказательством.
3. Серверное хранилище, шифрование, резервные копии, разграничение доступа и аудит до обработки реальных пациентских данных.
4. Измерить качество на одинаковых кейсах с независимой врачебной оценкой, включая ошибки, пропуски и небезопасные назначения. Сравнение с OpenEvidence/Doximity не выполнено, превосходство не заявляется.

## Переработанный механизм

Обновлённая архитектура, реальные форматы, смартфон, библиотека врача и ограничения описаны в [SYSTEM-DESIGN.md](docs/SYSTEM-DESIGN.md). Выполненные проверки и их границы — в [VERIFICATION.md](docs/VERIFICATION.md).

Клинический ответ теперь может содержать структурированный дифференциальный ряд, план уточнения, условную лечебную тактику, вопросы и контроль. Для простого вопроса к изображению используется завершённый профильный разбор без обязательного общего шаблона. Консилиум включается по выбору врача. Библиотека врача ищется локально по текстовым фрагментам; найденные фрагменты передаются внешней модели только при разборе.

Основная оболочка интерфейса доступна на десяти языках, язык ответа отдельно выбирается из 11 языков. Телефонный вход создаётся кнопкой в материалах случая; приложение показывает QR для устройства в той же локальной сети. Этот вход не публикует врачебные API и карточки.

Для локального чтения сложных PDF используются установленные Poppler `pdftotext`/`pdftoppm`. На этом компьютере их работа проверена. Без них сохраняется ограниченный собственный извлекатель текста, а скан может остаться непрочитанным с явным статусом.

Обновление интерфейса на десять языков, настоящий DOCX, стандартный VCF и события моделей в терминале: [UPDATE-LANGUAGES-DOCX-VCF.md](docs/UPDATE-LANGUAGES-DOCX-VCF.md).

## Журнал в терминале Cursor

Если приложение уже запущено, откройте в Cursor терминал этой рабочей копии:

```sh
cd /Users/maxmobiles.ru/Documents/ChatGPT/cosiliim
npm run logs
```

По умолчанию просмотр ждёт только новые события и объясняет, что нужно запустить разбор в приложении. Старые тестовые записи не выдаются за текущую ошибку. `npm run logs -- --history` показывает до 40 сохранённых событий с явной пометкой истории, затем новые события: этап обработки, выбранную задачу, вызванную модель и провайдера, HTTP-статус и причину завершения, токены, длительность, расчётную стоимость и факт получения клинического ответа. `length` означает обрезанный ответ модели; HTTP 200 сам по себе не означает успешно сформированное клиническое заключение. Один запрос связан общим идентификатором в квадратных скобках.

`Ctrl+C` останавливает только просмотр журнала, приложение продолжает работать. `npm run logs -- --json` показывает исходные JSON-события; `npm run logs -- --once` — разовый снимок. При `npm run dev` или `npm start` события также сразу видны в терминале сервера.

Локальный файл `.logs/events.jsonl` исключён из Git; при 2 МБ сохраняется один предыдущий файл. В журнал не включаются текст вопроса, имена и содержимое файлов, генотипы и API-ключи. Путь можно переопределить переменной `CONCILIUM_LOG_FILE` в окружении сервера и команды просмотра. Отдельно запущенная команда просмотра не читает `.env.local`.

В Cursor также доступно **Терминал → Запустить задачу → Concilium: журнал моделей** (конфигурация `.vscode/tasks.json`). Задача открывает отдельную панель журнала и не запускает второй сервер.

## Подключённые исходные модули Opus

Рабочие входы: `/radiology` — полная локальная станция DICOM, `/images` — выбор профильного разбора медицинских изображений, `/protocol` — отдельное оформление протокола. В карточке случая доступны переходы в Radiology и составление протокола. Разбор и протокол показывают потоковый предварительный ответ; VCF раскрывается локально ещё до запроса модели. Основная оболочка имеет десять языков, язык клинического ответа выбирается отдельно.

Источники кода, реальные проверки, порядок передачи результатов и оставшиеся ограничения: [MATERNAL-INTEGRATION.md](docs/MATERNAL-INTEGRATION.md). Установка ECGFounder обнаруживается на этом Mac автоматически. Для другой установки задайте `ECGFOUNDER_HOME`; для иной исходной Radiology — `RADIOLOGY_SOURCE_HOME`. На другой компьютер зависимости и веса необходимо установить отдельно.

Полное отдельное приложение «Протокол осмотра» встроено на `/protocol` с исходной коричневой палитрой, голосом, RAG, рецептурным редактором и экспортами. Краткий редактор доступен на `/protocol/structured`. Передача в карточку выполняется кнопкой внутри оригинального приложения. Подробности, расположение обеих языковых копий и ограничения: [PROTOCOL-ORIGINAL-APP.md](docs/PROTOCOL-ORIGINAL-APP.md).

На `/protocol` теперь два независимых варианта: самостоятельный русский протокол и многоязычный Doctor Opus Global. Global сохраняет собственную логику «диагностический черновик → дополнения врача → SOAP» и десять языков; оба варианта используют коричневый стиль, но не смешивают промпты, шаблоны и сохранённые документы.

- [Локальное хранение и проверка данных](docs/PRIVACY-AND-LOCAL-STORAGE.md).
- [План источников, лекарственной проверки и испытаний](docs/CLINICAL-EVIDENCE-ROADMAP.md).
- Самостоятельные приложения врача открываются из `/protocol` и `/translator`. Голосовой перевод использует настройки и авторизацию исходного `medical-translator`.
